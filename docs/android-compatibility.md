# Android 兼容性

安装要求：Android 8.0（API 26）及以上。APK 不依赖 Google Play 服务，也没有按 CPU 架构打包的原生库；不需要分别下载高通、联发科版本。

控制电脑时不需要录屏或无障碍权限。手机作为被控端时，录屏负责画面，无障碍负责点击、滑动和输入，两种权限不能互相代替。

| 系统 | 普通录屏 | 免重复录屏授权的兼容模式 |
| --- | --- | --- |
| Android 8–10 | 支持，需系统录屏授权 | 不支持系统无障碍截图接口 |
| Android 11 及以上 | 支持，需系统录屏授权 | 支持，需开启无障碍，约 3 FPS |

H.264 会检查系统编解码器能力；编码器不可用时可回退 JPEG。不能把模拟器的帧率当作真机性能，也不能因一台手机通过就承诺所有厂商的后台保活和自动解锁都相同。锁屏、PIN、强行停止和后台限制见[权限说明](permissions.md)。

## 回归环境

2026-09-09 对同一个签名 APK 完成了以下运行检查：

- Android 8 / API 26、Android 11 / API 30：无 Google 服务的 AOSP 模拟器。
- Android 16 / API 36.1：带 Google 服务的模拟器；同时检查拒绝通知权限后的被控启动。
- realme RMX5200 / Android 16 真机：覆盖安装后原配置和无障碍授权保留。

模拟器检查包含首次安装、覆盖更新、保存口令后的认证、实际录屏传输，以及正式 APK 的 1080P H.264 画面显示。独立查看端探针编译同一套产品代码，只向本机加密测试服务器发送输入，不操作真实电脑桌面。

三个系统各完成 41 项查看端界面 / 协议检查，覆盖两种鼠标模式、双指滚动、缩放、中文与表情组合输入、横竖屏、切屏、H.264/JPEG 切换和断线恢复。Android 8、16 首次全屏的系统教程暂停了脚本，确认教程后完成剩余四项，不把这次暂停算作应用崩溃。Android 8 另测了 720×1280、130% 字体下的工具栏和键盘。

未覆盖其他品牌真机、全部芯片、厂商省电清理、长时间后台运行或全部输入法。发现机型问题时，应记录 Android 版本、机型和应用内导出的诊断日志，不能只记录“黑屏”或“连不上”。

复测入口：`experiments/Start-AndroidCompatibilityEmulator.ps1`、`experiments/Run-AndroidLockProbe.ps1` 和 [查看端测试说明](../experiments/AndroidViewerProbe/README.md)。静止桌面可能只产生一帧，持续出帧测试必须配合画面变化。
