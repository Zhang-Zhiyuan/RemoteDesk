# Windows 窗口检查（2026-09-19）

本轮在私有 Windows 窗口站实际显示产品窗口并截图，不访问用户剪贴板、不启动被控端、不读取或保存用户设置，也不占用真实远控会话。

## 发现和修复

- 文件传输确认窗口在 150% DPI、1000×700 客户区、长中文文件名下出现整窗横向溢出；表格宽度达到 1026 像素，右侧“开始传输”按钮被裁切。单列表格补上 100% 列约束，长路径不再反过来扩大整个窗口。
- 继续缩小窗口后，原先直接使用 `TableLayoutPanel.AutoScroll` 无法可靠把表格滚入视口。确认和结果窗口改用外层滚动容器；内容在宽屏下仍占满可用高度，在窄屏下保持可用尺寸并支持 Tab 自动滚到选中控件。
- 文件名、原始位置和接收位置列设定可读的最小宽度，仅文件列表内部允许水平滚动；下方完整路径仍可选中和复制，避免列标题退化成一个字、用户误认保存位置。
- 结果窗口保留可选择、可滚动的完整回执及实际保存路径，增加可访问名称；关闭按钮不再被内容挤掉。

## 验证

`artifacts/audit-20260919/windows-ui/verified/layout.json` 记录 48 个通过的布局案例：

- 主窗口三页：1120、800、640、恢复 1120 逻辑像素宽度。
- 登录/部署服务器、设备密钥、共享名称四种对话框：700×500、480×300、340×230、恢复大窗口。
- 文件确认/结果窗口：9 和 14 pt 字体，各测试 1000×700、700×430、520×320、360×240、恢复 1000×700。实测设备 DPI 为 144（150%）；不是修改系统 DPI 后测试其他缩放级别。

检查包含正常聚焦后的可达性、整窗横向溢出、调整大小后的布局收敛。极窄窗口允许纵向滚动；不要求全部内容同时出现。截图已实际检查：

## 补查：偶发遮挡与显示不全

同日根据反馈继续检查 Windows 主界面、远控窗口和弹窗。证据位于
`artifacts/ui-clipping-20260919/`，仍使用私有窗口站和合成数据，不改正在使用的安装版本。

修复内容：

- 顶部说明和设备列表双行文字按实际字体高度布局，不再沿用固定高度。
- 长诊断文字使用独立纵向滚动区，进度条留在外层；长→短→长更新后重新校正滚动范围，末尾内容可达。
- 远控底栏根据当前窗口宽度把放不下的操作收进“更多”。两项放大选项保持在一起；菜单复用原操作，禁用和可用状态不变。
- 底栏按字体测量，调整窗口后等停靠布局结束再更新；高度很小时暂收起次要性能行，完整状态仍可悬停查看或右键复制。全屏隐藏工具栏时不重排其子控件，避免反复布局。
- 新增设备改为单列表单，设备密钥、共享名称、最新地址弹窗的说明和按钮可换行。最新地址列表内部允许横向滚动并明确标注 IPv6 端点。
- 修复弹窗内容变高后系统滚动范围仍停留在旧值的问题，防止底部确认按钮被裁切。

最终源码完整 Windows 测试在 `tests/windows-ui-final-verification.trx` 中为 2361 通过、11 跳过。中途有一轮旧测试 `DialogContentRetainsInputsAndActionsWhenViewportIsSmaller` 的输入框包含关系断言偶发失败；独立 6 轮及 UI 组 17 轮（每轮 267 项）均通过，目前没有定位到原因。保留原断言，增加仅失败时采集的几何诊断，没有靠删除断言或盲改产品掩盖；真实窗口的对应场景全部通过。这一间歇测试失败仍是记录中的未闭环项，不称为已修复。

实测系统 DPI 仍为 144。多档 DPI 的纯布局指标另有单测，但没有实际更改系统缩放或验证所有多显示器组合。未用这些布局检查替代远端输入/视频/公网实测，也未发布或覆盖运行中的应用。
