# 1.0.26 发布后的检查

以下为 2026-09-19 检查结束时的记录；后续打包发布见 [1.0.27](Release-1.0.27.md)。

本轮没有公开发布新版本，也没有覆盖 GitHub 的 1.0.26。为定位并修复 3080M 的锁屏故障，仅给这台已授权、空闲的设备安装了明确标识的内部诊断和修复候选；其余设备未替换。Linux、Android 改动尚未部署到真机。没有调整设备密码、网络路由或锁屏设置。

## 修复

- Linux 发送文件夹时，断线信号没有传入目录扫描和 ZIP 打包。现在扫描、压缩都能停止，并清理本次未完成的临时包；回归在真实临时文件和 ZIP 写入上复现了旧问题。
- Linux 大字体小窗口下，文件确认详情优先显示接收位置；完整原始路径、文本选择和滚动仍保留。实测 480×360 窗口，并验证滚动条能够到达最后一个字符。
- Android 取消接收文件列表、离开页面时，原来只丢弃结果，没有通知底层存储查询。现在传递取消信号，旧弹窗不能取消新请求，过期结果不会弹回页面。对于不响应取消的系统提供程序，仍只保留一个在途查询，不能保证强制终止。
- Windows 锁屏辅助服务把各种失败统一提示为“启用并管理员运行”。现在区分安装、停用、权限、连接、超时、响应错误等阶段；保留原有身份和权限校验，不自动安装或启用服务。
- Windows 更新后，共用同一个 EXE 的锁屏辅助进程可能仍映射到已改名的旧文件，被正确的身份校验拒绝。已增加严格限定条件的已有辅助服务重载：只允许当前管理员、已启用且归属正确、注册路径与当前程序完全一致、文件权限校验通过，并确认为程序路径不匹配的情况；不安装、启用或改写服务配置。停止/启动由独立、隐藏的固定用途短进程执行，不随主窗口正常退出而中断；不保证强制杀进程或系统关机中的恢复。实际恢复结果见下文。
- 文件确认 UI 的测试工具仍假定表格直接放在窗口下面，与新版滚动容器不符。已按控件用途查找，重新运行公网确认和取消流程；这是测试工具修复，不是另一个生产文件传输故障。

## 3080M 锁屏故障实测闭环

第二轮内部诊断候选确认故障为 `Executable` 路径不匹配；原生查询、SYSTEM 身份和会话检查均通过。本地自有子进程实验也复现了 EXE 运行中改名后，系统返回进程路径立即变化的行为。

第三轮修复候选 `1.0.27-candidate.3 / 20260919153835` 仅上传一次，设备回执确认 SHA-256。首次维护探针在重启离线窗口查询不到目录条目，提前退出；保留原始失败记录，未重传。随后独立只读验证两次通过相同设备 GUID 和新构建认证，均持续收到可解码 JPEG，原身份错误消失。

由于画面采样仅约 0.6% 非黑，未仅凭帧数判定正常：另外在确认仍为安全桌面后保存一张本地、不发布的截图并目检，清楚显示 Windows 锁屏时钟、日期及底部网络/电池图标。黑背景是真实锁屏内容，不是只剩鼠标的空白画面。静态画面去重后约 0.2 FPS，与重复帧统计一致。未发送输入、填写系统密码或尝试解锁，因此本次结论只覆盖锁屏捕获、更新恢复和公网重连。

3080M 当前保留该修复候选；恢复包未使用。源码改动和其他平台修复尚未公开发布。部署、两次重连和目检分别记录于 `windows-securedesktop/round3/3080m-candidate-deploy/`、`3080m-candidate-verify/`、`3080m-visual-check/`。

本机已安装的锁屏辅助服务，用新客户端只读查询返回普通桌面的 `inactive`，IPC 正常；没有为了测试锁住用户电脑。

## 未闭环的部分

- ADB 未发现手机，Linux 真机也不可达；本轮不证明这些物理设备已验收，也不替代六方向真机互联。
- Windows 全量中跳过的 11 项里，5 项 GPU 用例已单独实际执行通过，其余依赖外部真机输入/会话的用例本轮未运行；本次锁屏画面验证不替代键鼠与密码解锁验收。
- 之前记录的布局单测间歇失败，本轮未复现，不声称根因已解决。窗口矩阵不能保证所有 DPI、显示器组合均无问题。

证据保留在本机忽略提交的 `artifacts/audit-20260919-postrelease/`（Windows/公网）、`artifacts/audit-20260919-r2/linux/`（Linux）及 `artifacts/post-release-audit-20260919/android/`（Android）。

各轮候选只包含已审查的 Windows 诊断/恢复代码，不改变权限边界。部署前都另行准备基于已发布源码、构建时间更晚的前向恢复包；第三轮为 `1.0.26-recovery.3 / 20260919153921`，并以产品自身校验验证候选与恢复路径。原版安装包保持不变；没有绕过“不能安装更旧构建”的规则。包清单、源码指纹与验证报告在 `windows-securedesktop/` 下，恢复包均未使用。
