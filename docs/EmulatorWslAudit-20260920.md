# 模拟器与 WSL 实测（2026-09-20）

本轮基线是已发布的 1.0.27。Android 使用新建、无账号的 Android 16 模拟器；Linux 使用 WSL Ubuntu 24.04 内的独立 Xvfb/Openbox 桌面。所有输入、剪贴板和文件均为测试数据，没有操作用户的桌面或更改防火墙、路由。

后续已针对本次发现继续实现 Linux 自动文字剪贴板及安卓模式提示修复，结果见[后续修复记录](ClipboardAndStatusFollowup-20260920.md)。以下保留本次检查时的结果与边界，不将后续结果倒填为基线能力。

检查以实际输入、显示和保存结果为准，不以“已连接”作为通过依据。

## 已修复的界面问题

- Android：从系统界面停止屏幕共享后，录屏已撤销，但主页面仍显示“被控端正在运行”，恢复按钮未及时启用。正式包上等待 6 秒仍可复现。修复为仅在主页面处于前台时每 750 毫秒比较轻量服务状态，发生变化才刷新界面；页面暂停、销毁时取消检查，不在每次检查时枚举网络或刷新整页。
- Linux 远控窗口在小窗口、大字体下，原工具栏挤占画面。空间不足时现在把剪贴板、文件和放大操作放入“更多操作”，保留输入、发送、断开；放大窗口后恢复展开。
- 640×480、200% 字体的截图中，画面区域由约 90 像素增至约 310 像素。状态栏固定在底部，不再被操作栏裁掉。
- 窗口销毁时取消待执行的布局回调，避免快速调整大小后关闭窗口产生 Tcl 后台错误。
- 解码器的多行诊断原来会把底栏撑高。现在底栏显示单行摘要，双击或通过“更多操作 → 完整连接状态”查看、选择和滚动完整信息，不丢弃诊断内容。

## 已完成的检查

- Linux 的便携版使用原始启动脚本、随包 Python 运行时启动并正常退出；`.deb` 解包后的运行时及程序也实际启动。后者没有系统安装，因此不作为安装维护脚本的验收。
- Linux 正式包与修改后的源码分别运行真实 Tk 窗口检查，含三个主页面、设备对话框、文件确认和远控窗口；覆盖 100%、150%、200% 字体。
- Android 正式 APK 拒绝通知权限后仍能正常打开。历史保存、备注修改、进程重启恢复、连接失败不增加历史、使用节点自己的密钥重连、同一地址去重、取消删除和确认删除均已实测。前七项和后续六项报告分别保留，续跑使用原有数据。
- Android 接收文件列表的五项实测通过，包括真实 MediaStore 文件、完整接收位置、慢查询时 UI 响应、取消后不残留加载弹窗。
- Android 双指滚动检查 37 条断言通过，覆盖触屏/触控板模式下的抖动、反向、替换手指和缩放漂移。这是生成触摸事件的协议与手势检查，不代表所有真机的主观触感。
- Android 远控工具栏完成 9 组真实布局检查：240×480、320×480、360×640 dp，分别使用 100%、150%、200% 字体。每组检查 11 次按钮操作；横向操作行先滚动至目标按钮，再验证可见范围和真实坐标点击回调。最终截图停在滚动行末端，不表示左侧按钮不可访问。字体与窗口尺寸仅覆盖测试 Activity，没有改动系统字体或显示密度。
- Android 与隔离 Windows 生产协议对端最终 8 项检查通过：字符顺序、双向系统剪贴板、取消文件选择/取消确认不上传，以及确认后实际文件字节、保存 SHA-256 和回执。确认界面显示文件名、大小、接收设备及目标位置，完成后显示实际路径。
- Linux 与隔离 Windows 对端的手动文字剪贴板双向通过，含中文、emoji、换行和制表符。修改后的 Linux 客户端实际完成单文件和 ZIP 文件夹上传、SHA-256 保存回执及断开后重新连接；确认框显示源位置和接收位置，取消后未上传。
- 修改后的 Linux 客户端连接 Android 正式 APK 被控服务：真实录屏画面显示、按钮恰好点击一次、`WSL中文测试😀ToAndroid42` 完整进入安卓输入框。Android 录屏与无障碍均通过正常系统界面授权。
- Android 编译生产代码的隔离主控测试包连接正式 Linux 被控包：稳定连接内，原生按钮点击和中文、emoji 单次插入正确，真实系统剪贴板双向内容完全一致，最终 8 项检查通过。约 11 秒观察期内实际呈现 325 帧，约 29.5 FPS。这是本机隔离环境的数据，不是公网延迟或真机性能保证。

- Linux/Python 最终全量在独立 Xvfb 中执行 625 项，全部通过、无跳过；包含本轮新增的工具栏、菜单状态、关闭回调及完整状态详情检查。
- Android 修改后的 JVM 单元测试 666 项全部通过、无跳过；`lintDebug` 为 0 错误、6 条既有警告。Release 构建成功，但当前构建环境未加载发布签名，因此输出是未签名的验证产物，不是可发布的新版正式 APK。
- Android 状态刷新修复在独立测试包中完成 8 项实测：正常系统授权创建录屏、系统停止共享使录屏撤销、不切页面或手动刷新即显示停止状态、恢复按钮可用；点击恢复并再次正常授权后，完整重复一轮。以系统 `dumpsys media_projection` 和真实页面状态共同验证，不绕过系统授权。
- Android 最后的 6 项生命周期检查通过：实际服务日志确认两次启动，状态不变的前台及 HOME 暂停阶段没有持续刷新日志，清任务后 Activity 重建成功、无 Java 崩溃。此检查不等于 Handler 队列或内存泄漏的完整验证。

## 测试环境修正，不是产品故障

- 原安卓历史检查脚本依赖旧标签和旧页面布局，未滚动即判断历史不存在；已更新查找和滚动方式，不改变产品历史逻辑。
- Linux 的无边框测试输入框显示光标，不代表取得 X11 键盘焦点。Openbox 启动曾抢走焦点；测试靶现在只在点击自己的输入框时取得焦点。保留原失败报告。
- WSL 不能连入 Windows 临时监听端口，改用只访问本机测试端口的进程管道；没有修改防火墙。此管道不用于公网性能结论。
- Windows 合成文件接收端误把生产 API 返回的成功提示当作文件路径，导致保存后断线、没发回执。已修正测试端读取实际完成路径，保留失败证据；这不是生产文件接收器保存失败。
- Linux 首轮缩放后点击检查只等待网络收到帧，没有等待新尺寸实际呈现，因此第一下输入被产品正确忽略。检查改为等待实际呈现，并使用独立桌面的真实鼠标事件；Android 测试靶的按钮计数和文本随后均验证通过。
- Android 一轮输入检查期间发生两次默认网络切换，旧连接被替换。该轮不算稳定输入通过；另起稳定连接、校验整个输入阶段和呈现阶段属于同一连接后重新验证。
- Linux 反向剪贴板的测试设置程序曾在设置后退出，导致 X11 剪贴板持有者消失。改为测试期间保持前台 `xclip` 进程，并先独立读取确认内容存在，再从安卓读取；双向内容最终完全一致。原来的“远端没有可读取的文字”提示并非误报。

## 覆盖边界

- Windows 对端使用生产加密协议、独立窗口站的真实剪贴板及生产文件接收器；视频是合成图，鼠标输入只记录。不能把它算作 Windows 实际桌面输入验收。
- Linux 当前通过按钮及快捷键交换剪贴板；单纯改变剪贴板内容不会自动推送，不能宣称右键复制已全自动同步。Linux 主控端本轮的文件检查是上传，不是“取回文件”功能验收。
- 模拟器不代表小米、vivo 等厂商后台策略；WSL 的 X11 桌面不代表真实 Wayland、休眠或锁屏环境。Android 系统录屏授权限制仍存在。
- 本次新 AVD 没有 PIN。实际熄屏、唤醒后录屏仍保留，因此不能把该结果当作 Android 16 安全锁屏撤销录屏授权已经解决。
- 本轮改动尚未签名打包为正式新版，也未推送或替换已部署的 1.0.27。原 `release/RemoteDesk-Android.apk` 保持不变；安卓界面修复使用编译同一生产源码的独立测试包验证。

本地证据：`artifacts/emulator-audit-20260920/android/`、`artifacts/wsl-emulator-audit-20260920/`、`artifacts/audit-20260920-emulator-wsl/windows/`。测试口令仅在临时配置中，不纳入文档或发布包。

Linux 测试被控端及独立桌面已正常关闭；Windows 合成对端与两条 WSL 管道代理也已退出，监听和桥接子进程均已核对清空。相关临时测试密钥配置已删除，保留截图、校验和原始失败报告。

Android 新建模拟器中的三个测试安装包及其临时授权已移除，专用端口转发、测试对端进程已关闭；模拟器正常退出，相关监听端口为零。仅保留关闭的专用 AVD 及实测证据，没有清除其他模拟器或真机的数据。
