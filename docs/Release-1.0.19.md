# 1.0.19

主要改善公网远控的卡顿。

- Windows / Linux：H.264 的 TCP 传输持续积压时，自动切到最高 1080p，保留宽高比和硬件编码，不修改系统分辨率。稳定后尝试恢复一次；再次拥堵则本次连接保持流畅档，避免反复卡顿。
- Windows：重连时重新选择中继线路；换 Wi-Fi 或 IP 后，空闲连接会重新评估路线。无线传输优化只作用于实际承载视频的网卡。
- Windows 查看端：底部菜单增加“GPU 清晰增强（缩放时）”开关，硬件不支持时正常显示，不强制启用。
- Linux：剪贴板、文件确认和心跳等控制消息优先于下一张视频帧发送，避免被连续大帧抢占。已开始发送的加密帧仍保持完整。
- 三端：公网手动剪贴板操作最多等待 30 秒确认，减少慢链路误报；自动粘贴仍保留较短期限，过期回复不能覆盖新复制的内容。
- Android：修正静态画面或编码较慢时误降码率的问题；只使用实际写入耗时判断 TCP 压力，不混入加密和等待锁的耗时，也不混用 UDP 排队数据。
- Android：键盘弹出后按剩余可用高度调整工具栏，修复小屏、大字体下远程画面可能被挤没的问题。

1080p 缩放增强不能还原原生 4K 的全部细节。Windows 可关闭“自适应清晰 / 流畅”来固定尺寸；Linux 被控 CLI 可使用 `--no-adaptive-video`。安卓被控端仍沿用原有最高 1600 长边，不重复缩小。

本版沿用预发布标记。安卓沿用原签名；Windows EXE 未做 Authenticode 签名。Android 锁屏录屏授权、后台剪贴板及 Linux Wayland 的系统限制没有改变。自动化回归不能代替所有实体设备实测；设备替换结果另行报告。
