# RemoteDesk 私有公网中继

## 用途

私有中继用于位于 NAT/内网后的 Windows、Linux、Android RemoteDesk 互连。每个被控端
主动建立到公网 Linux 的 TLS 控制连接；发起远控时，再建立一条短期数据通道。
公网服务器只配对并转发不透明字节，RemoteDesk 原有口令证明、会话密钥协商和
AES 加密仍直接发生在查看端与被控端之间。

直连在“IP 直连”页使用；中继连接在“公网中继”页使用。中继不是开放代理，
没有正确随机访问密钥和已固定 TLS 证书指纹的客户端无法列目录、注册主机或建隧道。

## 服务器要求

- 具有公网 IPv4 或可解析到公网 IPv4 的域名的 Linux 服务器；
- systemd、Python 3.8 及以上、OpenSSL、util-linux（flock）；安装器可在 Debian/Ubuntu、Fedora/RHEL 系发行版
  上通过 `apt-get`、`dnf` 或 `yum` 补装 Python 3/OpenSSL；
- 可使用密码登录 SSH 的 `root`，或具有 `sudo` 权限的管理员账号；
- 云安全组和主机防火墙允许一个 TCP 中继端口，默认 `56567`；
- SSH 端口可自定义，默认 `22`。

服务器无需桌面、GPU、数据库、域名或公网证书。自动安装会生成自签 TLS 证书，
客户端通过 SHA-256 指纹固定它，而不是跳过证书校验。

## 配置步骤

1. 在第一台 Windows 机器打开“公网中继”，点击“配置/更新服务器”。
2. 填写公网服务器地址、SSH 端口、管理员账号/密码和中继 TCP 端口。
3. 等待界面显示安装成功。首次安装会创建专用低权限用户、配置文件、自签 TLS
   证书以及 `remotedesk-relay.service`，随后启用并启动服务。
4. 在其他 Windows 机器上填写同一服务器并再次配置。安装器会更新程序，但保留
   服务器已有的随机访问密钥和证书，因此这些机器进入同一个私有在线目录。
   程序与配置相同时直接复用运行中的服务，不重启、不打断已有连接；有更新或
   修改端口时才重启。多台机器同时配置时，服务端串行执行安装。
5. 被控机器设置 RemoteDesk 访问口令、启动“被控端”，并勾选“将这台电脑发布到
   在线设备列表”。控制机器刷新在线设备，选择目标并填写该目标的 RemoteDesk
   访问口令后连接。

在线列表会将当前电脑标注为“本机（不可自连）”。本机仍显示在线状态，但不能
通过中继连接自己；同名的另一台电脑不受影响，已有会话的远端也仍可按原规则接管。

### Android 首次连接

展开手机端“公网中转”，填写服务器地址和共享访问密钥，点“保存并连接”；端口留空默认
使用 56567。1.0.9 起会自动获取服务器身份，不需要手抄证书指纹。首次连接时确认一次
“信任并连接”，验证成功后加密保存，后续自动使用。首次配置应在可信网络中进行。

获取身份阶段不发送共享密钥；确认后会重新建立固定该身份的连接，再验证密钥。
取消、网络失败或密钥错误均不覆盖旧配置。已有身份不匹配时不会自动重新信任；确认
服务器确实重装或更换后，可在“高级设置”填写新指纹，并单独确认更新。

### IP 变化与地址上报

三端开启本机上线后，会在连接中继时上报当前 IPv4 地址和实际被控端口，并随每 10 秒的
心跳更新；也可点击“立即上报本机 IP”。这不会重启被控端或断开正在使用的中继会话。
网卡换地址后，只要仍能访问中继，新的地址会替换旧地址；控制连接失效时沿用原有自动重连。
上报使用固定设备 ID，同一台机器换 IP 不会生成重复的在线记录。

在线列表的“查看 / 使用 IP”会重新查询服务器，再把选定的地址和端口填到直连入口。
它只是地址提示，不代表这个 IP 从当前网络一定可达；程序不会用公网 NAT 的临时源端口冒充
被控端口，也不会自动连接未经用户选择的地址。跨网络或直连不可达时，仍可在在线列表点击
中继连接，不必记忆或修改目标 IP。

地址只在已认证的私有中继目录中可见，不上传远控口令，不写入公开日志，也不持久保存离线
地址。停止发布、被控端离线或心跳超时会移除在线记录；45 秒没有新的地址报告则不再展示
旧地址。多网卡最多上报 8 个可用 IPv4 地址，不包含回环、自动链路本地或组播地址。
列表每页最多 32 台，三端在同一个 12 秒总时限内读取并按设备 ID 去重。

服务器和客户端都需要更新到支持此功能的版本。旧版仍可正常中继连接，但不会显示地址；
新客户端连接旧服务器时会提示需要更新，不会为此跳过证书或访问密钥校验。

Windows 在线目录只在已配置中继、主窗口可见且选中“公网中继”页时定时刷新；收起托盘、
最小化或切到其他页会暂停目录轮询，恢复后会继续刷新。被控端的中继注册和心跳
独立运行，不会因隐藏窗口而下线或中断现有远控。

如果本机设置写入失败，主窗口顶部会持续提示“设置未保存”，而不是将未落盘的
配置报告为已保存。当前运行会保留更改；修复磁盘空间、目录或权限问题后点击
“重试保存”即可，不需要再次执行服务器安装。保存成功前退出软件会丢失未保存的更改。

Linux 管理员密码不会保存。服务器地址、管理员账号、SSH/中继端口和固定指纹会
保存在当前 Windows 用户设置中；中继访问密钥与远控口令由当前用户范围的 Windows
DPAPI 加密。不要复制 `settings.json` 代替在另一台机器上正常配置。
非 root 账号在同一次 SSH 命令内执行 sudo 和安装，兼容需要密码与免密 sudo。
安装参数通过权限受限的临时文件传入，访问密钥不出现在服务器子进程命令行。
SSH 主机指纹兼容 OpenSSH 的 `SHA256:` 前缀格式和 SSH.NET 的无前缀 Base64 格式，
也兼容旧版保存的无前缀指纹；只统一前缀与末尾填充，不改变密钥数据的大小写。
支持 `443` 等自定义 TCP 端口，但该端口须未被其他服务占用；更改后须同步各客户端。

### 中继更新保护（1.0.8 起）

Windows 的“配置/更新服务器”会检查服务端版本，拒绝降级和同版本不同内容的覆盖。
有远控或等待配对的会话时，更新会停止；请结束会话后重试。更新前保留私有备份，
更新后通过 TLS、访问密钥、运行中版本和源码哈希检查，失败则恢复旧文件和服务。
重复配置同一健康版本不会重启服务或更换证书、访问密钥。

备份位于服务器 `/var/lib/remotedesk-relay/update-*`，目录权限为 `0700`。
若断电、强制终止或回滚失败留下 `deployment-pending.json`，后续更新会停止并提示
备份位置；应先恢复，不能只删除提示文件继续覆盖。云安全组不由安装器修改，
本地健康检查也不代表云端口已对外放行。

旧客户端仍可连接中继，但它们的旧安装器没有这些保护。请先升级客户端，再使用
“配置/更新服务器”；只更新服务端，不能阻止持有 root 权限的旧安装器覆盖文件。

### Linux 与 Android 接入

服务器自动部署入口目前仍在 Windows。Linux / Android 接入**已配置的服务器**，
不会要求填写或保存服务器 root 密码，也不会修改服务器的现有密钥、证书或服务。
请通过可信渠道从管理员取得服务器地址、端口、共享访问密钥和 TLS 证书 SHA-256
指纹。共享访问密钥是服务器配置 `/etc/remotedesk-relay/config.json` 的 `access_token`，
不是 SSH 密码，也不是某台被控机器的远控口令；不要公开该文件或发进日志。

| 平台 | 配置与连接入口 | 本机发布到在线列表 |
| --- | --- | --- |
| Linux | 主界面“公网中转”页，保存配置，手动刷新并选择目标，填写目标远控口令 | 勾选发布本机，并从 GUI 启动本机被控端 |
| Android | 主界面展开“公网中转 · 配置与在线设备”，保存配置，点击在线设备；目标口令使用上方“连接口令” | 勾选发布本机，正常授权录屏并启动被控端；操作还需无障碍权限 |

Android 仅在页面前台且面板展开时每 15 秒刷新目录，隐藏后停止轮询；后台被控
注册不依赖面板轮询。Linux GUI 关闭/停止被控端、Android 停止录屏/被控服务时，
会关闭相应注册和数据连接。Linux 单独运行 headless host 脚本目前不读取 GUI 中转
配置，不应把“GUI 已支持中转”写成系统服务也已自动配置。

Android 将完整中转配置由 Android Keystore 加密保存。Linux 使用
`$XDG_CONFIG_HOME/remotedesk/relay.json`（默认 `~/.config/remotedesk/relay.json`），
原子保存并限制为 `0600`；这是文件权限保护，不是磁盘加密。两端均先验证固定
证书指纹，再发送共享访问密钥；错误指纹或密钥不回退到局域网直连。
切换配置会丢弃旧目录结果，不能通过旧行连接新服务器；本机 ID 不能连接自己。

2026-09-08 的真实公网中转六向记录与复测限制见
[三端公网中转验收](RelaySixDirections-20260908.md)。这不替代正式签名或长时间稳定性验收。

## 网络与画质

只需允许客户端主动访问公网服务器的中继 TCP 端口；两端内网无需开放入站端口。
自动安装可放行已启用的 UFW/firewalld，但无法修改云厂商安全组，需在云控制台手动
放行。中继模式不会尝试把局域网 UDP 地址跨 NAT 发送，而是使用同一条可靠 TLS/TCP
隧道承载 RemoteDesk 的加密 TCP H.264/JPEG、输入、剪贴板和文件消息。这优先保证
跨网可控性；时延和可用码率仍取决于两台机器到中继服务器的网络路径。

同城不等于低延迟。先分别测两端到中继的 RTT，再与两端直连比较；一个完整的
操作往返需经过两段线路。若到中继各需约 300 ms，经中继往返就可能超过 600 ms，
此时应检查出口绕路或换更合适的线路，降低画质不能消除这部分时延。
能直连的设备可使用“IP 直连”；明确选择中继时，程序不会静默切换连接路径。

Windows 数据通道保留 TCP 接收窗口自动调节，控制连接单独使用小缓冲；中继限制
尚未发送的 TLS 积压，不固定内核接收窗口，也不丢弃加密消息中的字节。握手与心跳
的长度头和正文合并写入，协议、分辨率和编码质量不变。

Linux 客户端也限制尚未发送的 TLS 积压，关闭超时会释放连接，避免影响重连。
Windows/Linux 在等待编码协商和 H.264 启动时限制 JPEG 预览，防止慢链路上
预览画面堵住后面的 H.264 和心跳；明确选择 JPEG、硬编码失败后的 JPEG 回退
仍按原来的画质和帧率运行。不发送编码协商消息的旧客户端在短暂宽限后恢复 JPEG。
三端查看端以完整、认证通过的消息判断入站连接是否活跃；慢网中仍在接收画面时，
不会仅因为 Pong 排在画面后面而误断开。残缺数据和认证失败不会刷新保活时间。
三端被控端的 Pong 在有界后台队列中回复，仍与画面使用同一个加密写锁；
慢速画面上传不会因为心跳回复堵住输入接收。队列最多一个正在发送、一个待回复，
断开时清空，发送失败会结束该会话。此优化不改变画质，也不能消除线路本身的 RTT。

三端的本机中转转接使用 16 KiB 的复制缓冲和小型回环收发窗口，回环被控连接也限制
发送积压。Linux 另限制异步预读和尚未发送的 TLS 数据，避免公网慢时先囤积数十帧
旧画面。限制只针对本机转接或待发送数据，不缩小公网接收自动调节窗口，也不改
分辨率、编码码率或 JPEG 质量；已开始发送的加密消息仍完整、有序发送。

管理员可在服务器配置中选填 `"tcp_congestion_control": "bbr"` 或 `"cubic"`，
仅作用于新的中继连接；缺省或空字符串沿用系统默认。内核不支持时回退，不修改
全局 sysctl。BBR 不是必然更快，应在空闲时对比同一条线路再决定是否保留。

## 运维与排障

### 多网卡选路

Windows、Linux 和 Android 的中继连接会尝试可用的网络路径，采用最先完成证书校验的
TLS 连接。目录、被控端注册和会话数据都使用这套逻辑；未选中的连接不会发送访问密钥，
也不会注册重复设备。优选结果缓存一分钟，网络信息变化或连接失败时重新选择。
缓存路径有短暂优先机会，失败后立即尝试其他路径；不会为测速强制切断现有远控会话。

Windows/Linux 的可选网卡与 DNS 探测有 250 ms 预算，超时或枚举失败就沿用系统连接；
这不会跳过系统连接自身的域名解析和证书校验。取消后的迟到结果不会重新发起连接。
Android 单网络和多网络拨号共用 12 秒总超时，涵盖 DNS、TCP 和 TLS，取消会关闭所有
候选套接字。后台拨号最多 8 个线程、64 个排队任务，避免异常 DNS 下反复重连积压。
域名会交替尝试 IPv4/IPv6 地址，最多 4 个；第一个解析地址不通时继续回退，所有地址
仍须通过相同的证书指纹校验。保存新的中继配置也会立即取消旧目录请求。

Windows/Linux 的自动比较目前针对多网卡上的公网 IPv4 中继；IPv6、内网地址及检测到
的活动隧道沿用系统路径。Android 的其他网络探测也只针对公网 IPv4，混合内外网地址的
解析结果沿用系统路径；只比较已连接、已验证、不受限且非计费的其他网络，
不启用移动数据、不绑定整个进程。无法绑定某个网卡时回退到正常系统连接。
Windows/Linux 可用环境变量 `REMOTEDESK_RELAY_SYSTEM_ROUTE_ONLY=1` 停用自动比较。

这不是带宽叠加，也不能保证绕过系统的路由或转发策略。若指定网卡仍走错出口，需要
检查实际数据包和路由；界面显示的“本地地址/端点”只表示连接使用的源地址，不作为
物理出口证明。编码、分辨率和画质设置不随选路改变。

Windows 的“自动优化双网卡中继线路”默认开启。以管理员运行、配置的是公网 IPv4
地址且存在多个物理出口时，首次连接前最多用 8 秒比较经过证书校验的 TLS 握手。
系统线路已经较快就不改路由；另一条线路连续两次明显更快才保留中继地址的 `/32`
临时路由。主机名、IPv6、非管理员运行或检测到 VPN/虚拟网关时沿用普通连接。

临时路由只覆盖该中继 IP，但它属于系统路由，因此同一 IP 上其他程序的新连接也
可能使用它。检测到该 IP 已有 TCP 连接或已有专用路由时，不做试切；既有会话期间
只续期当前路由，不反复追逐更低延迟。不修改默认路由、网卡优先级或系统转发设置。

路由有效期为 90 秒，运行中每 20 秒核验归属、网卡和网关后续期；退出时仅删除自己
创建且标记未变的路由。异常退出没有清理机会时，由 Windows 到期撤销。网关变化、
路由失效或线路连续无响应时，释放临时路由并关闭本进程对应的中继连接，触发现有
自动重连。正常收包时不额外测速，也不因一次探测失败中断画面。关闭界面选项或设置
`REMOTEDESK_RELAY_SYSTEM_ROUTE_ONLY=1` 可停用；Linux/Android 不使用此 Windows 路由功能。

实现依据：[Windows 套接字接口选择](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)、
[Linux 套接字设备绑定](https://github.com/torvalds/linux/blob/v5.15/net/core/sock.c)、
[Android Network.bindSocket](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.Socket))。
Windows 临时路由使用 [MIB_IPFORWARD_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_ipforward_row2)
的有限有效期，并通过 [GetIfEntry2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getifentry2)
识别物理网卡。

在服务器上可运行：

```bash
sudo systemctl status remotedesk-relay
sudo journalctl -u remotedesk-relay --since today
sudo ss -lntp | grep 56567
```

若“读取在线设备失败”，依次检查 systemd 状态、云安全组、中继端口和 DNS。
目录请求有超时与取消处理；超时会清空过期列表并允许重试。安装成功但中继端口
无法访问时，界面保留连接失败原因。注册连接通过心跳确认在线状态，断线或
持续无响应后自动重连，停止被控端会关闭该连接及其数据通道。
若设备不在列表，确认该设备的被控端已启动且勾选了本机上线。若 SSH 或 TLS 指纹
意外变化，客户端会明确拒绝连接；先在可信控制台核实服务器是否重装或证书是否
被替换，再重新配置，不能通过关闭证书验证绕过。

需要在已授权公网服务器上实际验收时，可使用
[交互式公网中继测试工具](../experiments/RelayPublicProbe/README.md)。它调用应用自身的
自动部署、注册、查看端和加密协议代码，覆盖原样画面传输、输入消息、重连和重复
安装；不会控制真实桌面，也不会把管理员密码保存到文件。公网测试须手动执行，
不属于默认单元测试。吞吐及延迟结果只代表当次网络路径，不代表服务器套餐上限。

卸载服务：

```bash
sudo systemctl disable --now remotedesk-relay
sudo rm /etc/systemd/system/remotedesk-relay.service
sudo systemctl daemon-reload
```

`/etc/remotedesk-relay/config.json` 含共享访问密钥，权限限制为 root 与专用服务组可读。
删除配置目录会让旧客户端失去访问能力；重新配置后需在每台客户端再次配置以取得
新的密钥和 TLS 指纹。
