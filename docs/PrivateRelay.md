# RemoteDesk 私有公网中继

## 用途

私有中继用于位于 NAT/内网后的 Windows、Linux、Android RemoteDesk 互连。每个被控端
主动建立到公网 Linux 的 TLS 控制连接；发起远控时，再建立一条短期数据通道。
公网服务器只配对并转发不透明字节，RemoteDesk 原有口令证明、会话密钥协商和
AES 加密仍直接发生在查看端与被控端之间。

直连在“IP 直连”页使用；中继连接在“公网中继”页使用。中继不是开放代理，
没有正确随机访问密钥和已固定 TLS 证书指纹的客户端无法列目录、注册主机或建隧道。

## 服务器要求

- 具有公网 IPv4 或可解析到公网 IPv4 的域名的 Linux 服务器；
- systemd、Python 3.8 及以上、OpenSSL、util-linux（flock）；安装器可在 Debian/Ubuntu、Fedora/RHEL 系发行版
  上通过 `apt-get`、`dnf` 或 `yum` 补装 Python 3/OpenSSL；
- 可使用密码登录 SSH 的 `root`，或具有 `sudo` 权限的管理员账号；
- 云安全组和主机防火墙允许一个 TCP 中继端口，默认 `56567`；
- SSH 端口可自定义，默认 `22`。

服务器无需桌面、GPU、数据库、域名或公网证书。自动安装会生成自签 TLS 证书，
客户端通过 SHA-256 指纹固定它，而不是跳过证书校验。

## 配置步骤

1. 在第一台 Windows 机器打开“公网中继”，点击“配置/更新服务器”。
2. 填写公网服务器地址、SSH 端口、管理员账号/密码和中继 TCP 端口。
3. 等待界面显示安装成功。首次安装会创建专用低权限用户、配置文件、自签 TLS
   证书以及 `remotedesk-relay.service`，随后启用并启动服务。
4. 在其他 Windows 机器上填写同一服务器并再次配置。安装器会更新程序，但保留
   服务器已有的随机访问密钥和证书，因此这些机器进入同一个私有在线目录。
   程序与配置相同时直接复用运行中的服务，不重启、不打断已有连接；有更新或
   修改端口时才重启。多台机器同时配置时，服务端串行执行安装。
5. 被控机器设置 RemoteDesk 访问口令、启动“被控端”，并勾选“将这台电脑发布到
   在线设备列表”。控制机器刷新在线设备，选择目标并填写该目标的 RemoteDesk
   访问口令后连接。

在线列表会将当前电脑标注为“本机（不可自连）”。本机仍显示在线状态，但不能
通过中继连接自己；同名的另一台电脑不受影响，已有会话的远端也仍可按原规则接管。

Windows 在线目录只在已配置中继、主窗口可见且选中“公网中继”页时定时刷新；收起托盘、
最小化或切到其他页会暂停目录轮询，恢复后会继续刷新。被控端的中继注册和心跳
独立运行，不会因隐藏窗口而下线或中断现有远控。

如果本机设置写入失败，主窗口顶部会持续提示“设置未保存”，而不是将未落盘的
配置报告为已保存。当前运行会保留更改；修复磁盘空间、目录或权限问题后点击
“重试保存”即可，不需要再次执行服务器安装。保存成功前退出软件会丢失未保存的更改。

Linux 管理员密码不会保存。服务器地址、管理员账号、SSH/中继端口和固定指纹会
保存在当前 Windows 用户设置中；中继访问密钥与远控口令由当前用户范围的 Windows
DPAPI 加密。不要复制 `settings.json` 代替在另一台机器上正常配置。
非 root 账号在同一次 SSH 命令内执行 sudo 和安装，兼容需要密码与免密 sudo。
安装参数通过权限受限的临时文件传入，访问密钥不出现在服务器子进程命令行。
SSH 主机指纹兼容 OpenSSH 的 `SHA256:` 前缀格式和 SSH.NET 的无前缀 Base64 格式，
也兼容旧版保存的无前缀指纹；只统一前缀与末尾填充，不改变密钥数据的大小写。
支持 `443` 等自定义 TCP 端口，但该端口须未被其他服务占用；更改后须同步各客户端。

### Linux 与 Android 接入

服务器自动部署入口目前仍在 Windows。Linux / Android 接入**已配置的服务器**，
不会要求填写或保存服务器 root 密码，也不会修改服务器的现有密钥、证书或服务。
请通过可信渠道从管理员取得服务器地址、端口、共享访问密钥和 TLS 证书 SHA-256
指纹。共享访问密钥是服务器配置 `/etc/remotedesk-relay/config.json` 的 `access_token`，
不是 SSH 密码，也不是某台被控机器的远控口令；不要公开该文件或发进日志。

| 平台 | 配置与连接入口 | 本机发布到在线列表 |
| --- | --- | --- |
| Linux | 主界面“公网中转”页，保存配置，手动刷新并选择目标，填写目标远控口令 | 勾选发布本机，并从 GUI 启动本机被控端 |
| Android | 主界面展开“公网中转 · 配置与在线设备”，保存配置，点击在线设备；目标口令使用上方“连接口令” | 勾选发布本机，正常授权录屏并启动被控端；操作还需无障碍权限 |

Android 仅在页面前台且面板展开时每 15 秒刷新目录，隐藏后停止轮询；后台被控
注册不依赖面板轮询。Linux GUI 关闭/停止被控端、Android 停止录屏/被控服务时，
会关闭相应注册和数据连接。Linux 单独运行 headless host 脚本目前不读取 GUI 中转
配置，不应把“GUI 已支持中转”写成系统服务也已自动配置。

Android 将完整中转配置由 Android Keystore 加密保存。Linux 使用
`$XDG_CONFIG_HOME/remotedesk/relay.json`（默认 `~/.config/remotedesk/relay.json`），
原子保存并限制为 `0600`；这是文件权限保护，不是磁盘加密。两端均先验证固定
证书指纹，再发送共享访问密钥；错误指纹或密钥不回退到局域网直连。
切换配置会丢弃旧目录结果，不能通过旧行连接新服务器；本机 ID 不能连接自己。

2026-09-08 的真实公网中转六向记录与复测限制见
[三端公网中转验收](RelaySixDirections-20260908.md)。这不替代正式签名或长时间稳定性验收。

## 网络与画质

只需允许客户端主动访问公网服务器的中继 TCP 端口；两端内网无需开放入站端口。
自动安装可放行已启用的 UFW/firewalld，但无法修改云厂商安全组，需在云控制台手动
放行。中继模式不会尝试把局域网 UDP 地址跨 NAT 发送，而是使用同一条可靠 TLS/TCP
隧道承载 RemoteDesk 的加密 TCP H.264/JPEG、输入、剪贴板和文件消息。这优先保证
跨网可控性；时延和可用码率仍取决于两台机器到中继服务器的网络路径。

## 运维与排障

在服务器上可运行：

```bash
sudo systemctl status remotedesk-relay
sudo journalctl -u remotedesk-relay --since today
sudo ss -lntp | grep 56567
```

若“读取在线设备失败”，依次检查 systemd 状态、云安全组、中继端口和 DNS。
目录请求最多等待 12 秒；超时会清空过期列表并允许重试。安装成功但中继端口
无法访问时，界面保留连接失败原因。注册连接通过心跳确认在线状态，断线或
持续无响应后自动重连，停止被控端会关闭该连接及其数据通道。
若设备不在列表，确认该设备的被控端已启动且勾选了本机上线。若 SSH 或 TLS 指纹
意外变化，客户端会明确拒绝连接；先在可信控制台核实服务器是否重装或证书是否
被替换，再重新配置，不能通过关闭证书验证绕过。

需要在已授权公网服务器上实际验收时，可使用
[交互式公网中继测试工具](../experiments/RelayPublicProbe/README.md)。它调用应用自身的
自动部署、注册、查看端和加密协议代码，覆盖原样画面传输、输入消息、重连和重复
安装；不会控制真实桌面，也不会把管理员密码保存到文件。公网测试须手动执行，
不属于默认单元测试。吞吐及延迟结果只代表当次网络路径，不代表服务器套餐上限。

卸载服务：

```bash
sudo systemctl disable --now remotedesk-relay
sudo rm /etc/systemd/system/remotedesk-relay.service
sudo systemctl daemon-reload
```

`/etc/remotedesk-relay/config.json` 含共享访问密钥，权限限制为 root 与专用服务组可读。
删除配置目录会让旧客户端失去访问能力；重新配置后需在每台客户端再次配置以取得
新的密钥和 TLS 指纹。
