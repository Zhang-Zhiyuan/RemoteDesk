## 网络结果不能略去

首次走本机有线时，HYX JPEG 写入持续受阻，剪贴板确认超时，测试失败。
同一时间附近的只读 TLS 测量：有线三次约 769 / 717 / 1406 ms；Wi-Fi 首次失败，后两次约 30 / 33 ms。
后续产品自动选到 Wi-Fi，手机会话往返约 30–115 ms，另一次稳定在 38–43 ms；HYX 全套通过，剪贴板确认约 44 ms。

这些是不同含义的测量（TLS 建连耗时与会话心跳 RTT），不能混为帧到屏延迟。
没有禁用网卡、改变路由、降低画质或缩短防抖策略来让测试通过。有线弱网失败证据保留，不能保证该链路的拥堵已被消除。

## 本轮修复

- Android 接收重复 `.txt` 文件，实机回执出现 `name.txt (1)`。所有文件此前都标成 `application/octet-stream`。
  现在按已清理的文件名，使用系统 MIME 映射；公共下载目录和应用文件分享共用相同规则，未知类型仍用二进制。
  [Android 的文件名分拆规则](https://android.googlesource.com/platform/frameworks/base/+/android10-release/core/java/android/os/FileUtils.java)说明了 MIME 不匹配时扩展名为何会被当作文件名的一部分。
  Android 16 模拟器对照复现旧问题，修复后 TXT/大写 TXT/ZIP/未知扩展名的重名保护、内容、MIME、回执及清理共 14 项通过。
- Linux 能力列表遗漏 DeviceIdentity 和 HostVideoDiagnostics 的名称，出现 `Unknown(4194304)` 等提示。只补名称，不增加实际声明的能力。

验证：Android Debug/Release 各 732 项单测通过、零跳过；两种 lint 均零错误；Release 构建成功。
Linux 名称回归 4 项在本机和 HYX Python 3.10 均通过，相关低延迟回归 135 项通过。
