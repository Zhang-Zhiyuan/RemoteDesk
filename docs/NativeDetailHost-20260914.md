# 原生补清：正式会话实测

2026-09-14。Windows 被控端和查看端现已接入原生补清，不再只是组件原型。
旧报告保留当时的限制和失败记录，以本页说明当前接入范围。

## 使用范围

远控窗口新增“原生补清”开关，默认关闭，与原来的 GPU 缩放增强并列。
目前仅支持新版 Windows 控制 Windows、单个未旋转的显示器及兼容的 D3D11 / 硬件 H.264 驱动。
Linux、Android 和旧 Windows 对端仍用原有协议，不会收到未协商的新记录。

底图仍是 H.264；鼠标附近最多 1024×1024 的区域在停止操作后逐步补充无损原始像素。
它不猜字，也不承诺全屏瞬间变清晰。带宽紧张、持续输入、窗口太小或驱动不可用时不补清。
开启时视频走可靠通道，已有 UDP 鼠标通道保留；关闭后经双方确认恢复 UDP 视频。
不修改系统分辨率，不改变原有默认模式。

## 本轮修复

- 用一次 DDA 取得的原生 GPU 纹理同时生成 H.264 底图和细节，避免两次截图拼出错字。
- 静态桌面可继续完成补清；GPU 精确比较处理系统上报的大片脏区，缺少证据时撤掉旧块。
- 已确认的稳定块不重复发送。真实接收反馈决定细节预算，不把写进中继本地缓冲当作公网带宽。
- 沿用当前已经自适应降低的传输尺寸，开启补清不会把 1080p 重新拉回设置上限 4K。
- 每个可选分片最多 633 字节（含加密记录开销），预算最多为观测吞吐的 4%、上限 1 Mbps。
  抢不到发送锁立即让路；输入、拥塞和显示积压时不排队等补清。
- 关闭、输入、换尺寸立即撤销本地补清。硬件临时不可用也能发送关闭请求；快速开关不会让迟到的开启覆盖关闭。
- UDP 恢复带独立帧序列边界，旧数据包、校验包和重放确认不能恢复旧画面；第一张新 UDP 帧到达前仍接收 TCP 底图。

原生缓存上限 4 MiB / 64 块，压缩任务、GPU 读回和发送队列均有独立上限。
GPU 比较仍有计算成本；非阻塞不等于零开销。

## 真实 Windows 主机 / 公网中继

使用本机 RTX 2080 Ti，主屏完整覆盖自建 3840×2160 中文桌面夹具，副屏运行真实查看窗口。
正式主机发送 1920×1080 H.264，真实接收端缓存逐字节对比原始 RGBA。
公网测试使用指定的私人 TLS 中继和临时随机设备标识，无直连回退，没有替换已有在线设备。

| 检查 | 本地加密连接 r10 | 真实公网中继 r3 |
| --- | --- | --- |
| 默认关闭，普通画面可用 | 通过 | 通过 |
| UI 开关 → GPU 采集 / 硬编 → 实际 GPU 补清 | 通过 | 通过 |
| 连续 12 秒补清、收到的块与原图完全一致 | 64 块 | 27 块 |
| 中文输入即时撤销旧补清，空闲后恢复 | 通过 | 通过 |
| 连续两轮关闭 / 重开 / 普通画面恢复 | 通过，UDP 恢复两次 | 通过，可靠通道保持 |
| 显示失败计数 | 0 | 0 |

每个输入阶段实测 12 次，输入均注入探针自己已确认前台焦点的文本框，不写入用户应用。
计时是本机客户端入队到主机窗口 `TextChanged`，公网情况包含实际往返中继路径中的输入传输，
**不是屏幕显示或玻璃到玻璃时延**：

| 输入阶段 | 本地中位数 / 最大值 | 公网中位数 / 最大值 |
| --- | --- | --- |
| 普通模式 | 11.35 / 33.99 ms | 24.84 / 106.62 ms |
| 原生补清开启 | 11.30 / 14.69 ms | 23.35 / 86.79 ms |
| 关闭后 | 10.92 / 15.38 ms | 24.86 / 36.76 ms |

样本量有限，不能据此保证所有网络、GPU 或手机都不增加延迟。
公网输入测试期间补清曾因反馈余量不足暂停数秒，底图和输入继续工作；没有为了好看而放宽预算。
开启阶段查看端“接收至提交呈现”的分桶 P99：本地约 0.75～1.00 ms，公网约 1.75～2.00 ms。
这是软件提交时间，不含 DWM / 显示器完成；冷启动和切换的较大尾延迟保留在原始报告中。

早期主机 r4 / r5 的像素不匹配由夹具窗口被遮挡导致；r6 在捕获前查出遮挡。
此后增加真实 Z 序和持续覆盖检查，r7 / r8 / r10 通过。r9 因探针未取得输入焦点中止，
修复探针焦点确认后才进行输入实测，未绕过焦点检查发送文字。
