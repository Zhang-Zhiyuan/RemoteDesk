# Windows 界面卡顿检查（2026-09-14）

这轮处理的是 Windows 程序的界面响应，不是手机端，也没有调整网络路由、视频码率或远端分辨率。

## 查到的问题

1. 观看 4K JPEG 时，高质量缩放在主界面线程执行。运行跟踪落在 `BufferedPictureBox.OnPaint → GdipDrawImageRectI`，单次约 90–120 ms，主窗口和远程窗口都会受影响。
2. FPS、延迟等数字更新会调用 `LayoutStatusFooter`，重新测量和排列整排按钮。隔离运行跟踪抓到一次约 647 ms 的停顿，发生在 `SetPerformanceStatus → LayoutStatusFooter → Button.GetPreferredSize`。这条路径也用于 H.264。
3. 主窗口缩放时，即使没有跨越响应式布局断点，也会重建表格行列样式。权限面板的系统查询、扫描中的网卡查询也有同步运行在界面线程上的部分。

## 修改

- JPEG 和软件解码帧的缩放移入后台，保留原来的高质量双三次算法。结果直接写入自有 DIB；正常 `WM_PAINT` 只拷贝准备好的像素，不在界面线程重新缩放。
- 后台和界面之间使用仅保留最新帧的有界队列，不增加定时等待。窗口大小或显示模式改变时，可使用原图兼容绘制；原始图像尺寸和输入坐标映射不变。
- 添加捕获代次、硬件显示代次检查，防止晚到的软件帧盖住更新的 H.264 GPU 画面。关闭、替换、失败分支释放本轮新增的位图资源。
- 性能数字变化只重绘文字；详情行有无、尺寸、DPI、按钮等布局条件变化时才重排。相同几何布局不重复执行整排布局。
- 主窗口同一断点/DPI 下复用行列样式；展开权限面板后异步查询系统状态；设备扫描的网卡枚举和本机地址过滤在后台执行。

H.264 GPU 解码/缩放算法、新版放大开关、JPEG 压缩质量均未更改。权限查询采用按需后台执行，并不表示程序里所有系统查询都已后台化。

## 验证

性能探针运行在独立 Windows 桌面上，使用真正的 `RemoteViewerWindow`、合成 3840×2160 图像和原生绘制 DC；不读取用户桌面、剪贴板或发送输入。两种路径预热后分别连续收帧 5 秒，再等待尾帧。

最终复测，显示区域 3530×2036：

| 指标 | 原绘制路径 | 优化路径 |
| --- | ---: | ---: |
| 界面绘制平均耗时 | 111.43 ms | 4.22 ms |
| 界面心跳间隔 P95 | 139.51 ms | 32.02 ms |
| 界面心跳最大间隔 | 150.36 ms | 36.68 ms |
| 已解码图像入队至绘制完成，平均 | 121.51 ms | 121.00 ms |
| 已解码图像入队至绘制完成，P95 | 143.18 ms | 134.63 ms |
| 提交 / 观察到的帧 | 39 / 39 | 41 / 41 |

前一轮修完状态栏后也没有丢失提交帧，心跳最大间隔为 35.43 ms。以上是本机合成场景，不是公网端到端延迟保证；探针上限 15 FPS，包含输入位图生成时间，实际提交速率低于该上限。

- 画质：7 组尺寸，包含 4K、竖屏、放大、缩小、文字和细线。同时检查原 `OnPaint` 与原生 `WM_PRINTCLIENT` 路径。多数对比最大通道差不超过 1；4K 居中绘制有少量差 2 的样本，BGRA PSNR 约 75 dB。测试只在 PSNR 不低于 70 dB 时允许这类两单位取整差异。
- 行为：窗口/模式变化的兼容绘制、原图尺寸、位图所有权转交、关闭释放、过期软件帧拦截、有界准备队列、性能文字不触发布局、相同布局不重复排列。
- 定向回归：250 项通过。
- 最终 Windows 全量回归：2203 通过，6 项需要独立交互环境的测试跳过，共 2209 项；启用了硬件 smoke 开关。
- 本轮早先的 Python 回归：528 通过、49 项平台相关跳过，共 577 项。

首次扩大回归时，一个已有的真实 FFmpeg 解码测试失败，单独及全量复跑均通过。保留了失败日志，并给断言补充了提交序号和解码器失败详情，没有删掉或跳过该测试。

## 测试中淘汰的方案与边界

- 仅后台缩放后再调用 GDI+ 绘制的初版，在连续收帧时额外增加了约 40 ms，未安装。
- 分块并行和不同混合方式没有带来稳定收益，未保留在产品中。最终不是分块算法，也没有引入新的缩放滤波器。
- 早期私有桌面探针可能因遮挡跳过绘制；后续改为显式驱动真实绘制路径。对原生拷贝的计时使用原生 DC，不使用会额外复制像素的内存 `Bitmap.GetHdc` 路径。
- 早期主窗口尺寸压测的读取与设置 DPI 坐标不一致，已经修正；不能拿那组数据计算前后提速比例。
- 此次没有证明公网链路延迟已经改善，也没有改动其他设备或 GitHub Release。

原始日志、跟踪和安装核验保存在本机 `artifacts/windows-ui-20260914/`，未加入仓库。最终性能数据为 `software-final-confirm/software-pipeline.json`，全量结果为 `tests/windows-ui-final.trx`。
