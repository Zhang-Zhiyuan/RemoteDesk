# 2026-09-07 公网中继实测与修复

在用户明确授权的 Ubuntu 24.04 公网服务器上调用应用自身的自动安装代码验收。
未安装额外操作系统更新，未更改 SSH 配置、云安全组、其他服务或本机用户设置。

## 实测发现并修复

1. SSH.NET 返回无前缀 Base64 指纹，而从 OpenSSH 取得的固定指纹带 `SHA256:`。
   原实现会把同一把密钥误判为变化。现在两种形式与末尾 Base64 填充统一处理，
   保持密钥内容大小写敏感，真实密钥变化仍拒绝连接。
2. SFTP 权限 API 要求 `700`/`600` 这样的 chmod 数字，而不是十进制位掩码
   `448`/`384`。原实现实测在目录权限设置阶段抛出 `ArgumentOutOfRangeException`，
   自动安装无法完成。现在用命名常量传入正确权限，上传密钥前目录限制为所有者可访问。
   [SSH.NET 对应版本的权限实现](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/Sftp/SftpFileAttributes.cs)
   明确规定了该格式。

新增 8 个离线回归场景：指纹格式、空值、幂等性、大小写保护，以及直接调用实际
SSH.NET 依赖验证两种权限的解析与所有者隔离；这两类错误均先复现失败再修复。
`RelayProvisionerTests` 共 19 项通过。

## 公网验收

新增手动工具 [RelayPublicProbe](../experiments/RelayPublicProbe/README.md)，密码仅隐藏
输入，不进入参数、环境变量、源文件或输出文件。首次完整验收 12 项通过，加入
RemoteDesk 应用协议验证后的第二轮 13 项通过：

- 默认 TCP 56567 自动安装、TLS 访问及在线目录。
- 错误共享访问密钥、错误 TLS 指纹均被拒绝。
- 被控端注册、心跳、忙碌状态、查看端 3 次重连和被控端重新注册。
- 双向各 1 MiB 随机载荷 SHA-256 一致。
- 保持隧道时重复安装，不改变访问密钥、证书或服务 PID，不打断传输。
- 真实 RemoteViewerClient 通过中继完成 RemoteDesk 口令认证和加密协议交互。
- 1920×1080 合成 JPEG（50,188 字节）原样到达并成功解码；4 条鼠标/键盘按下与
  释放消息按序到达合成被控端。中继模式没有误启用局域网 UDP。
- 测试结束后合成设备从在线目录移除，服务继续运行。

服务器服务已启用开机启动，使用专用非 root 用户；配置和私钥权限 640，未发生
异常重启。部署的 Python 服务文件 SHA-256 与工作区源文件一致。

## 性能观测与边界

本机直接 ping 服务器 4 次平均约 319 ms；两次双端经中继的小包往返中位数约
643/669 ms，第二次有约 1.77 秒的最大值。双向各 1 MiB 回环传输分别耗时
42.16/54.82 秒，合计有效吞吐约 0.40/0.31 Mbps。服务内存约 14 MB，CPU 累计
消耗低于一秒。该结果显示当前公网路径存在较高延迟与吞吐限制，不能仅以编码
画质参数解释卡顿，也不能据此断定云服务器的带宽套餐或所有客户端网络的上限。

测试双端运行在本机，经实际公网中继往返；这不是两个独立运营商内网的实机测试。
合成被控端只解码输入消息，没有对用户桌面注入鼠标/键盘。真实桌面捕获、输入权限、
H.264 硬件编解码和长时间稳定性没有在此次公网测试中验收。不能据此声称所有功能无 bug。
