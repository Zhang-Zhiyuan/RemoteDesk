# 文件传输确认与结果

发送文件、粘贴文件和拖放现在会先向当前被控端查询接收目录。确认框列出文件名、大小、源位置和接收位置；长路径可以在下方完整查看。取消确认不会发送文件数据。

完成后统一显示逐项保存回执，包括重名后的实际文件名、校验结果和失败原因。取回文件会列出本机保存路径。文件夹仍以 ZIP 传输，不会自动解压。

“粘贴到远端当前窗口”是单独的操作请求，不能保证那个窗口接受粘贴，也无法可靠报告它的最终路径。界面明确区分这个请求和已经保存的接收副本。

## 相关修复

- 排队中的文件操作仍绑定原连接；换设备后必须重新确认，不会发给新连接。
- 批量发送中断时保留已有成功回执，逐项列出未完成项目。
- 取回文件后即使本机剪贴板被占用，仍显示已保存文件的真实路径，并保留剪贴板重试；不把剪贴板失败误报成文件未保存。
- 安卓公共下载目录通过自己创建的 MediaStore 记录读取实际文件名，不再把原始文件名当作保存结果。无法读取元数据时显示文件 URI；公共下载失败时明确说明应用目录的后备位置及卸载影响。
- Windows 先清除旧连接能力和更新占用状态，再发出断线通知，修复回归中捕获的偶发状态残留。
- Linux 被控页下拉框适应窄窗口、大字体；文件确认框增加完整路径区域，修正说明文字背景。

协议通过能力位 27 协商控制消息 38/39，不改变 DeviceInfo 格式，也不新增端口。直连和公网中继使用同一加密通道。旧端未升级时明确显示“位置未确认”，不会假装已获知目录；新端查询失败或超时则在发送前停止。

## 本轮验证

- Windows：2,224 项通过，11 项硬件/真机门控测试跳过；另外验证目录查询超时、错误编号、旧端兼容和排队时连接切换。
- Linux/WSL：586 项通过，包括 Xvfb 下真实确认/结果窗口和大字体窄窗口布局。新协议使用与 C#、Java 相同的中文/表情 UTF-8 样例。
- Android：625 项单元测试通过，Debug 构建和 lint 完成；lint 无错误，6 条现有警告。
- 公网中继：11 项通过。使用临时注册节点、生成的测试文件和产品接收器，检查 1 MiB 字节一致性、重名保留、空文件、负回执、混合成功/失败批次、文件回传、确认前不发送以及结果弹窗的真实路径。操作的仅是测试窗口，不读取或覆盖交互桌面的剪贴板。

证据位于 `artifacts/file-locations-20260918/`：公网中继 JSON、Windows TRX、Linux 日志和两端窗口截图。早期失败记录保留用于复核，最终结果以 `windows-delivery-verified.trx`、`clipboard-save-result-verified.trx`、`linux-full.log` 和 `relay-delivery-verified` 为准。

本轮未检测到 USB 手机，未计入 Android 真机验证。本机仍有中继会话，未强制重启或覆盖正在运行的程序；本轮不推送 GitHub 或升级生产设备。
