# 右 Shift 与修饰键检查

## 已确认的问题

- Windows 会把部分右 Shift 事件带来的错误扩展标记原样发出，并在被控端生成 `E0 36`。本机中文、US 键盘布局的原生映射均不能识别它；正确扫描码是 `36`。发送端和接收端现在都修正这一种错误，右 Ctrl、右 Alt、小键盘回车等真正的扩展键不变。
- Windows 的低级键盘钩子与窗口消息对同一修饰键可能分别报告左右专用 VK 和通用 VK。切换输入来源后，旧代码不能配对按下和松开，可能留下修饰键状态。现在按物理侧别匹配，保留原按下命令用于释放，覆盖查看窗口、被控端、锁屏辅助进程和会话快捷键。
- Linux 的 Shift+Tab 实际产生 `ISO_Left_Tab`，旧映射漏掉 Tab。新增映射，并兼容旧 Windows 发出的错误右 Shift 扩展标记。Linux 被控端也按实际注入的左右侧别合并通用 VK 与专用 VK，避免松开后仍残留状态；没有扫描码的通用修饰键保持原来的左侧含义，不误清右侧。
- 安卓被控端此前会把 Ctrl+Shift+C、Ctrl+Meta+V 等当作普通复制粘贴，也会把不支持的组合键降级为手机的单键导航动作。现在不再这样处理，并跟踪左右修饰键；文字输入仍使用原来的 Unicode 文本通道。

## 检查方式

Windows 先运行新增回归测试，旧实现 21 项中失败 12 项。另用旧 DLL 的纯模拟输入复现 8 组换源释放残留，不读取实体键盘状态、不锁屏。

`InteropProbe keyboard-modifiers-isolated` 在独立 WindowStation 内运行真正的 WinForms 查看窗口，通过临时回环端口完成认证、输入传输和解码，再使用系统键盘映射及独立的合成按键状态验证字符。8 组场景检查右 Shift+A/1、两侧同时按下、Ctrl/Alt、失焦释放及真正的扩展键。没有调用 SendInput、接管真实远端、修改键盘布局或读取用户剪贴板。

Linux 在 WSL 的独立 Xvfb 内使用真正的 XTest 输入和 Tk 事件，经过产品查看端的按键处理、序列化和解码，检查侧别、大小写、Shift+Tab 及释放。安卓本轮通过单元测试检查输入与快捷键状态，未操作手机。

完整日志保存在本地忽略的 `artifacts/audit-20260921-keyboard`、`artifacts/right-shift-audit-20260921`、`artifacts/audit-20260921-linux-keyboard` 和 `artifacts/android-modifiers-20260921`。

## 回归结果

- Windows 主测试集：2,578 通过，11 跳过；NativeDetail：53 通过。跳过项需要显式启用 GPU 或真实远端输入，未计为通过。
- 独立 Windows 查看窗口的按键协议与原生映射：8/8 通过。
- 独立 Windows 剪贴板与快捷键链路：13/13 通过，覆盖右 Ctrl+V、Ctrl+Shift+V、Shift+Insert、焦点变化和中文/emoji 文本。Linux/安卓在这组测试中是模拟的协议对端，不代表真机或输入法候选窗验收。
- WSL/Linux 全量：698/698 通过，0 跳过，包含独立 Xvfb 内的实际按键检查。
- 安卓 Debug、Release 单元测试各 717/717 通过，0 跳过；lint 均无错误，分别有 6、5 条警告。警告涉及现有文案、解锁尝试状态的同步持久化及 Debug manifest 叠加声明；检查合并后的 Debug manifest，文件 provider 仍为 `exported=false`。日志保留了修复前的失败用例及最终结果。

## 范围

这轮检查不等于所有键盘布局、实体键盘、Wayland 或手机厂商系统都已验收。安卓查看端仍使用本地文本框提交文字，没有新增原始外接键盘透传功能。源码修复不会自动改变已安装的 1.0.28；发布和覆盖安装应单独核验。
