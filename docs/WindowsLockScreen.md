# Windows 锁屏控制

在被控电脑的“被控端”页面打开“被控权限设置…”→“设置锁屏控制…”→“安装 / 更新锁屏控制”，授权安装一次。新版 Windows 程序启动时默认申请管理员权限，按系统 UAC 提示确认即可；旧版可在同一设置区点击“授权并重启应用”。管理员启动不等于自动安装锁屏控制服务，后者仍需启用一次。卸载此功能可在锁屏控制菜单选择“停用锁屏控制”。

连接后按 Windows 原来的登录方式操作：

- 时钟和壁纸页面：先点击或按键，展开登录页。
- 无密码账户：点击“登录”，也可以在登录按钮有焦点时按回车。
- 密码 / PIN 账户：选择对应的“登录选项”，在 Windows 输入框填写。不要把 RemoteDesk 的连接口令当成 Windows 密码。

RemoteDesk 不设置、修改或保存 Windows 登录密码，也不关闭锁屏或 UAC。远程 Win+L 会调用系统锁屏接口；断线时释放本连接按下的键。只在已认证的远程会话期间申请保持显示和系统工作，断线即释放，不修改电源计划。

熄屏不等于整机睡眠。系统仍在运行时，连接会申请唤醒并保持显示；本机按电源键、合盖或显式选择睡眠，不保证能被这个请求阻止。S3 睡眠 / S4 休眠期间程序不能继续接收普通远控连接，需要另行配置硬件唤醒；当前版本没有通过公网中继唤醒已睡眠电脑的功能。参见 [Windows 睡眠状态](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/system-sleeping-states) 和 [电源保持请求](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)。

慢速中继上的锁屏 JPEG 可能比普通 H.264 画面大很多。查看端现在会识别正在接收的数据包，避免整帧尚未到齐就触发 18 秒心跳超时；停传仍按原超时断开，单包等待最多 90 秒，且完整消息仍须通过认证后才能显示。Windows 和 Android 查看端都采用这一限制，不改分辨率或图像质量。此修复需要更新查看端，不能仅更新被控电脑。

2026-10-18 工作树实测：2080Ti 锁屏并关闭显示器后，已安装的主机程序在认证连接时重新亮屏，直连首帧约 0.9 秒；锁屏鼠标移动、按键及断线释放均通过。相同主机经公网中继，旧查看端未收到整帧就超时；修复后的查看端收到正常 3840×2160 锁屏画面，但当时链路首帧仍需约 46 秒。该结果验证的是避免误断线，并不代表公网带宽问题已解决，也不是 S3 睡眠唤醒验收。未更改密码、锁屏或电源策略。

2026-10-19 补测：2080Ti 改走已保存的 Guest Wi-Fi 后，锁屏并熄屏的中继探针收到原生 3840×2160 首帧约 1.23 秒。REDMI 已安装收包超时修复候选版，随后真实 REDMI→2080Ti 会话的主机日志显示锁屏恢复到普通桌面，并持续超过 10 分钟未出现同类断线；但查看端在 H.264 分辨率切换后退回 JPEG，不能把这次连通性通过当成流畅度验收。隔离 GPU 测试中复现并修复了同一窗口重建显示资源报拒绝访问的问题，REDMI 安装后实测仍有 JPEG 回退，因此不能认定这就是该机的完整原因。

Windows 查看端现已取消解码失败时自动请求切换 JPEG：先尝试 H.264 软件解码；组件未就绪或解码失败时，以 1、2、4、8 秒上限退避等待独立关键帧重建解码器，保持连接并丢弃陈旧待解码帧。恢复到正常 H.264 后清除退避。此限制不拒收主机发来的锁屏 / 启动 JPEG，也不影响用户手动选择 JPEG。协议回归已验证恢复路径只请求关键帧，不改成 JPEG-only；仍需分别验证受影响电脑的实际解码恢复与网络质量。

同日从 REDMI 取回的 02:25:06 解码错误为 `The presenter changed before the decoded frame could be submitted.`：解码完成前显示资源已变化，却被当成永久硬解错误，随后因 FFmpeg 未就绪而请求 JPEG。修复在创建硬件显示资源前使旧软件预览失效，并将过期显示资源的输出单独丢弃；不会停用仍正常的解码器。隐藏窗口的真实 GPU 回归已覆盖同一 HWND 上“解码—显示资源销毁—丢弃旧帧—下一帧重建并继续硬解”。

02:58 的 REDMI→2080Ti 实际会话保持 H.264，但用户仍报告卡顿；主机发送约 17–19 FPS、6–7 Mbps，持续 TCP 写入积压，有线到中继的 ICMP 往返约 310 ms。新增的发送节奏控制仅在连续证实 TCP 带宽不足时减少独立帧发送数量，保留编码质量、分辨率和硬编热态，不对健康链路、UDP 或依赖参考帧链另加限速；恢复帧可立即通过，带宽缓解后缓慢升帧。固定 48 KiB 模拟画面经过真实加密 TCP 和限速回环桥的隔离对比中，接收帧龄中位数约 441→118 ms，稳态约 10.7→9.6 FPS；这是排队控制测试，不是实际公网延迟或解码显示验收。网络基础 RTT 不会被该策略消除。

同次检查还发现：Guest 掉线后有线已重连，旧临时路由的定时清理却再次关闭同一服务器的新连接。现在清理和健康流量检查按“服务器地址 + 本地出口地址”限定范围；两条不同本地地址到同一端点的真实套接字回归已验证旧连接关闭后新连接继续传输。

1.0.27 修复了更新后辅助进程仍使用旧文件、导致锁屏无画面的问题。更新后会检查已启用且属于当前用户的辅助服务，符合恢复条件才重新加载；不会自动安装或启用已停用的服务。

1.0.28 处理登录桌面屏幕标识变化：原屏幕不可用且登录桌面只有一个物理屏幕时临时使用该屏幕，解锁后恢复原选择；有多个候选时不会随意改选，会提示切换屏幕。画面切换或采集失败期间拒绝旧坐标点击，不自动重放输入。此项通过隔离的屏幕布局、协议和输入队列回归，不等同于已完成真实密码 / PIN 解锁验收。

如果主程序与锁屏辅助服务分装在不同目录，1.0.28 更新后还会检查并升级已启用的旧辅助服务。只有属于当前用户、位于受保护安装目录且通过更新校验的程序才能参与；不新建服务，不启用已停用的服务，也不更改启动方式。升级成功后会启动仍处于启用状态的服务。启动或身份检查失败时尝试恢复原配置和原运行状态；检测到外部配置变化则停止处理。配置检查不是系统级原子事务，更新期间请勿同时更改服务。便携目录不用于注册系统服务。

当前范围是已登录用户的本机控制台会话锁屏。开机后尚未首次登录、其他用户 / RDP 会话、要求专用 Ctrl+Alt+Del 安全注意序列的入口，以及指纹 / 人脸 / 安全密钥验证，尚不属于已支持的范围。

2026-09-10：无密码账户已做完整锁屏—解锁实测；密码 / PIN 所需的按键、数字和 Unicode 输入已有协议回归测试，尚未用真实带密码 / PIN 的 Windows 账户完成登录验收。
