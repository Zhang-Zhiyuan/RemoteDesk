# 剪贴板与状态提示修复（2026-09-20）

接续模拟器 / WSL 检查，补齐 Linux 主控端自动文字剪贴板，并修正安卓被控模式的指引。只操作独立 Xvfb、私有 Windows 窗口站和专用 Android 16 AVD，没有读取用户桌面的剪贴板或更新生产设备。

## Linux

- 连接后分别记录两端基线，不在刚连上时交换旧内容。正常文字变化自动同步；空内容不清空对端，两端同时改变时保留各自内容并提示选择方向。
- 正式协议同时声明 `ClipboardText` 与 `ClipboardSnapshotV1`，自动读取使用独立请求 ID。旧端不支持时保留按钮和快捷键并提示，不冒用旧版无 ID 回复。
- 本地内容读取放在后台，有时限和大小上限；不在 Tk 界面线程等待外部剪贴板应用。手动操作优先，断线后旧会话失效。
- X11 使用内容、所有者及 XFixes 事件标记校验新复制，应用远端内容前再次验证；避免回传循环。文件 / 图片不会作为空文字覆盖，也不会偷偷上传文件。
- 缺少可靠元数据的环境保守关闭自动取回，仍可自动发送有变化的文字或手动取回。Wayland 尚未实机验收，不宣称与本轮 X11 等同。

XFixes 提供的是选择所有权变更通知，不是对所有应用“用户点击了复制”的监视。[X.Org 协议说明](https://xorg.freedesktop.org/archive/current/doc/fixesproto/fixesproto.txt)

### 实测与保留的失败

`experiments/wsl_clipboard_auto_audit.py` 启动真实 Linux GUI 和独立文本窗口，通过鼠标打开复制 / 粘贴菜单，与生产协议的隔离 Windows 对端交换真实系统剪贴板。

- `baseline-2`：正式 1.0.27 确认右键复制后远端仍保持旧内容。这是负对照，不计作功能通过。`baseline-1` 的测试窗口被远控窗口遮挡，已修正测试窗口置前，保留失败证据。
- `source-1/2`：新实现首次握手漏声明 `ClipboardText`，生产 Windows 对端按协议拒绝快照；实测发现后补齐，并加入能力组合回归。
- `source-3`：正常右键自动发送已经通过；延迟注入抓到未变化快照，前置检查判失败。测试改为有界请求时序屏障，确认真正延迟了指定的旧内容，未修改产品决策或回复。
- `source-4`：普通 Tk 文本窗口的同值重新复制没有新事件且 `TIMESTAMP=0`，旧回复覆盖了新复制意图。该失败保留，不宣称 XFixes 能识别不存在的事件。
- 后续带 `--assert-selection` 的用例明确让测试窗口通过自己的 Tk 连接释放、重新声明所有权，再执行正常复制。它验证有真实系统事件时的保护，不替代或掩盖上一个不可观测边界。

对不报告事件的同值重新复制，可使用“发送本机剪贴板”明确指定方向；没有通过全局输入监视、强占用户剪贴板或丢弃富文本格式来猜测操作。

最终源码的普通 Tk 实测 `source-6-manual-fallback` 为 15/15：普通文字右键复制自动发送、远端变化自动取回后本地右键粘贴、上述同值复制的显式按钮兜底、过期回复隔离、无回传循环、空内容保护和断线重连均通过。报告分别标明自动步骤和显式按钮步骤。

同一最终源码的 `source-7-final` 为 14/14：测试窗口明确发布 X11 复制事件，约 3 秒的迟到回复未覆盖随后重新复制的同值内容；冲突提示、再次复制恢复同步、双向系统剪贴板、无回传、空内容及重连保护均通过。没有把它当作无事件应用的通过结果。

刻意让独立剪贴板所有者停顿 2.5 秒，3.5 秒观察期仍有 113 次 UI 心跳、最大间隔约 38 毫秒，并收到 16 个测试视频帧。此结论仅覆盖新增自动同步路径；旧的显式按钮读取仍使用 Tk，不据此宣称其面对异常所有者也不会等待。

最终 Linux/Python 回归在独立 Xvfb 中执行 658 项，全部通过、无跳过。检查源码 SHA-256：`7226fef5ab66f64f9ccb502b1a89834d5b2e7a3b5e53da71ae662a72471f1b18`。
