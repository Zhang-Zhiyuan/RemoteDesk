# 手机远控第二轮复查（2026-09-08）

沿用上一轮真实手机与独立 ViewerProbe，本轮重点检查边界情况，没有更改
Windows/Linux 被控端、中继、手机网络或系统权限策略。

## 找到并修正的问题

| 问题 | 修正 |
| --- | --- |
| 重复 DeviceInfo 会取消正在进行的拖动 | 只有控制权限代次变化才重置手势；UI 使用当前权限，不使用排队回调里的旧权限快照 |
| 直接触摸模式从黑边开始无法双指缩放 | 保留本地双指识别；黑边仍不能触发远端点击、拖动或滚轮 |
| 缓慢开合手指时，缩放少算开始的一段距离 | 识别意图前保留初始间距/中心，识别后按完整间距比例缩放 |
| 已拖动后加入第二根手指可能误发右键 | 只有未移动、未按住鼠标的真正双指轻触才触发右键 |
| 切屏等待时，新屏幕名称下仍显示旧 H.264 画面 | 立即隐藏旧 Surface 和指针，清除旧画面，提示等待新画面；期间阻止新输入但允许释放原鼠标 |
| 空文字发送误报为队列忙 | 空草稿禁用发送，有文字才启用，发送成功后清空并禁用；仅观看状态不发送输入，也不触发拖动震动反馈 |

## 回归结果

- **376 项 Android 单元测试通过**：57 个测试套件，0 失败、0 错误、0 跳过。
  新增 8 项手势/权限 UI 回归；其中黑边缩放、缓慢缩放、拖动后双指误触三项
  在修改前确实失败，并非只新增了原本就能通过的测试。
- **41 项真机检查全部通过**：13 项边界/故障注入 + 28 项常规 UI、输入与画面检查。
  真机为 realme GT8 Pro / RMX5200，Android 16 / API 36。
- 修改前真机边界流程 13 项中有 3 项失败：DeviceInfo 打断拖动、黑边缩放、切屏残留旧 Surface。
  同一流程在修复后全部通过。
- 额外验证了仅观看/恢复控制、切屏暂缓出帧、主动切断 TCP 后自动重连。
  重连使用新连接代次，未重放旧输入；未主动断线的常规 UI 流程保持同一 TCP 会话。
- 上轮的中文及表情输入、快捷键顺序、左右键、拖动锁定、横竖屏与输入法布局、
  1:1、JPEG/H.264 双向切换、多屏选择、全屏恢复和返回确认均重新执行。
