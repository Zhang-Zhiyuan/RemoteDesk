# 三端中继互控实测

2026-09-22，基于 1.0.31 检查 Windows、RMX5200 真机、Android 16 模拟器和 2080 Ti Ubuntu 22.04 实机。以下连接均经过已有公网中继，没有用局域网直连代替中继。

## 六个方向

| 控制端 → 被控端 | 本轮实际验证 |
| --- | --- |
| Windows → Linux 实机 | 产品客户端连接独立测试桌面；11 项协议/功能检查通过：认证拒绝、画面、屏幕选择、剪贴板写入、双向文件传输、重名/空文件/文件夹、JPEG/H.264 切换、会话替换和两次重连。接收文件另做哈希核对。 |
| Linux 实机 → Windows | 使用已安装产品的 Tk 查看器，画面显示、点击和中文/emoji 输入成功；Windows 测试窗口实际收到了输入。 |
| Windows → 安卓真机 | 画面、点击、拖动、返回/主页、文本输入；向手机传入签名候选 APK，通过系统安装器覆盖安装，保留原数据和权限。 |
| 安卓真机 → Linux 实机 | 使用手机产品界面连接；点击计数、32 次拖动事件、中文/emoji 均在 Linux 测试窗口核实；取回剪贴板、粘贴文字成功。通过系统文件选择器发送文件，检查发送前确认和接收位置提示，接收文件 SHA-256 一致。 |
| Linux 实机 → 安卓真机 | 使用产品 Tk 查看器，通过中继接收手机画面；向下/向上滚轮及 Home 按键在手机实际生效，修复前后均有截图。 |
| 安卓真机 → Windows | 07:29–07:33 补测：RMX5200 产品界面选择临时 Windows 节点，经公网中继完成认证、Surface H.264 解码；Windows 实际测试窗口收到 1 次点击及完整的 `RMX5200 to Windows 中文😀 0922`。此前模拟器结果只保留为附加回归，不替代此次真机验证。 |

Linux 使用独立 Xvfb 和独立配置目录，但运行的是实机的 Python、FFmpeg 和 NVIDIA GPU，不是 WSL 替代实机。没有操作用户的真实登录桌面。Windows 输入仅发往专用测试窗口；失去前台时停止测试。

## 修复的问题

1. **安卓被控滚轮方向相反。** 桌面滚轮与触摸滑动的方向不是同一个符号。修正映射，滚动距离和时长不变；已用 Linux 产品界面对真机复测。
2. **远程逐字输入密码可能把原内容替换成掩码。** Android 13+ 改用[系统无障碍输入连接](https://developer.android.com/reference/android/accessibilityservice/InputMethod.AccessibilityInputConnection)向当前编辑器提交文字和退格，不读取密码原文，也不借用剪贴板。真机原来无法通过的随机设备密钥，修复后可正常登录测试主机。旧系统保留普通文本路径，对不可安全重建的密码不再做破坏性替换。
3. **安卓在线列表周期刷新会跳回上面。** 请求过程中不清空列表；数据未变时保留原视图、滚动和焦点。设备状态、地址、共享名称及操作权限改变时仍刷新。
4. **安卓设备名/多地址显示超出按钮。** 单独调整多行设备按钮的换行和内边距，保留完整地址。
5. **Linux 健康的 NVENC 会被短暂停顿误判为故障。** 实测出现 H.264 约 30 FPS 后永久回退 JPEG 的情况。将“编码器失效”判定与“画面是否过期”分开：失效宽限为至少 2 秒，旧帧有效期仍是 0.5 秒，最新帧单槽、不排队的策略不变。

NVENC 在实机上做了故障注入：仅暂停本测试启动的 FFmpeg。旧实现遇到 0.9 秒暂停会淘汰编码器；修复版连续三次保留原进程，恢复后约 5–16 ms 得到新帧；持续暂停 2.3 秒仍触发回退。这是编码器恢复测量，不是公网端到端延迟。

## 回归与边界

- Android Debug、Release 各 736 项单元测试通过。API 36 模拟器上另外完成 26 项实际输入检查（含密码、点击后立即输入、emoji 退格和选区删除），以及 9 项按钮宽度/字体缩放检查。
- Linux 在 WSL 跑 740 项自动测试：711 通过，29 项需额外桌面条件的测试跳过；本轮实机 GUI、GPU 和中继检查单独记录，不能把这些跳过项算成通过。
- 手机作为被控端仍使用原有无障碍兼容采集，约 3 FPS。没有为提帧率更改用户的录屏授权或锁屏策略。手机控制 Linux 时实际验证了 Surface H.264 解码。
- 没有覆盖所有厂商/旧版 Android、真机双指手势、Wayland、锁屏解锁及长时间网络抖动。因此本记录不是“所有场景无 bug”的保证。
- 新的密码输入路径依赖 Android 13+ 的系统接口；旧系统或不提供编辑连接的特殊控件仍有能力限制。

本轮实测结束时，签名候选 APK 已安装在 RMX5200；正式 Linux 安装目录及 Windows 安装未替换。当时未提交 Git、推送或创建新 Release，正式包仍是 1.0.31；不能仅凭候选 APK 的同名版本号认定其他设备也有这些修复。后续发布归入 1.0.32，见[发布说明](Release-1.0.32.md)。

本地原始记录在 `artifacts/interop-20260922/`，不纳入 Git：`windows-linux-features/`、`windows-target-r2/`、`linux-gui-postfix/`、`phone-evidence/`、`nvenc-recovery-result.json` 及构建日志。临时中继节点、测试桌面和窗口已关闭；手机上本轮新增的临时连接记录已删除，原有记录保留。HYX 上约 5.4 MB 的本轮临时目录已删除，所需日志和截图在本地保留。

## 手机虚拟导航键（07:00 后追加）

Windows、Linux、安卓控制端均新增“返回、主页、最近任务”。只对 Android 远端显示，仅观看时禁用；继续使用原协议的 Esc、Home、F12，手机无需增加权限或更新被控协议。完整按下/抬起成组入队，拒绝错误平台、过期会话和队列不足；导航前结束自己的拖动/按键，避免粘住修饰键。

- Windows → RMX5200：点击真实 WinForms 按钮，手机实际进入最近任务、返回和主页；核对连续画面、仅观看禁用和切换 Windows 远端后隐藏。小窗口优先保留返回/主页，其余操作可在“更多”找到。
- HYX Linux → RMX5200：在实机独立 Xvfb 上运行修改后的 Tk 查看器，实际按钮逐个调用成功；500×540 小窗口内三个按钮均可见，没有越界。
- Android 控制端的按钮布局做了 6 组尺寸/字体检查（240–720 dp 宽、320–640 dp 高、1–2 倍字体），每组通过坐标点击及只读/平台切换检查。这些仅是模拟器上的 UI 回归，不是另一台实体安卓被控机的测试。
- 本次回归：Windows 全量 2735 通过、11 跳过；之后新增小窗口优先级用例，相关 250 项通过。Android Debug/Release 各 737 项通过；Linux 743 项中 714 通过、29 跳过。

真机补测首次启动 Windows 测试板时，前台被已有 RemoteDesk 窗口切走，测试保护在发输入前停止；该次记为中止，不能算通过。确认空闲后重新测试，实际窗口始终拥有前台且输入结果匹配。

追加证据：`physical-phone-windows-r2/`、`navigation-windows-real-phone/`、`navigation-linux-real-phone/`、`navigation-layout-*.json`。实测结束时，导航功能仅在源码与测试构建中，尚未替换正式安装或发布 GitHub Release；手机此前安装的 1.0.31 候选包不包含这次新加的控制端导航栏，需升级到 1.0.32。
