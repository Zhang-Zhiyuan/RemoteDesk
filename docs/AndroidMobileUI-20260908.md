# Android 手机远控界面与操作检查（2026-09-08）

后续修正与最新测试包见[第二轮复查](AndroidMobileUI-Recheck-20260908.md)；本文保留第一轮记录。

本次只调整手机作为**控制端**时的远程桌面界面、输入与画面切换。
没有更改 Windows/Linux 被控端、私有中继配置、手机锁屏或其他远控软件。

## 操作方式

底部固定为「键盘 / 触控板（直接触摸）/ 鼠标 / 屏幕 / 更多」，主要按钮
触摸高度 48dp。顶部保留简短连接状态，点击查看完整诊断；横屏收起次要信息。

| 操作 | 行为 |
| --- | --- |
| 触控板（默认）单指滑动 | 移动指针，不按住鼠标 |
| 轻触 / 连续轻触 | 左键点击 / 双击 |
| 长按后滑动 | 拖动，抬手或取消时释放 |
| 直接触摸 | 点按定位点击，单指滑动拖拽；黑边不触发点击 |
| 双指轻触 / 平行滑动 | 右键 / 远端滚轮 |
| 双指开合 | 本地缩放，可同时平移，不发送远端 Ctrl+滚轮 |
| 鼠标面板 | 左键、右键、拖动锁定；切换模式、失焦、退出会释放 |
| 键盘 | 手机输入法完成组词后点发送；快捷键直接发送到远端 |
| 屏幕 | 按被控端提供的列表切换；未支持此能力时禁用 |
| 更多 | 适应窗口、原始像素、画质、全屏、方向、帮助、诊断、断开 |

横屏输入使用单行「文字 / 按键」切换，临时隐藏顶部状态条，给远端画面留出
可见区域。已放大的画面在弹出键盘时保持像素大小（受 1–8 倍缩放边界限制），
并将本地指针保持在可见区域。竖屏显示快捷键和文字输入两行。
输入草稿最长 128 个 UTF-16 单元，不持久化；输入队列忙时保留草稿。
返回先收起输入/鼠标面板或退出全屏，再次返回才询问是否断开；全屏保留工具栏恢复按钮。

交互组织参考了[向日葵 Android 控制端手册](https://sunlogin.oray.com/news/16428.html)
中的工具栏、模式、键盘及屏幕选择方式；实现和视觉资产使用本项目自己的代码。
中文输入依赖原生 EditText/InputConnection 完成组词，不把拼音中间态逐字发送。
相关平台接口见 [Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)。

## 实测中修正的问题

- JPEG 预览之后切换 H.264，旧 Surface 不存在时会等待无法到来的首帧：
  现在先准备零透明度 Surface，再等待解码确认后显示。
- 画质/屏幕切换的迟到 JPEG 解码任务可能覆盖新画面：增加展示代次校验，
  解码前后、提交到 UI 前都核对。同尺寸 H.264 切屏也重置解码器 Surface 代次，
  让无逐帧回调设备重新进行首帧确认。
- 横屏隐藏状态行时仍沿用竖屏测量值：不再在布局回调中修改子控件可见性。
- 横屏输入法挤掉整个远程画面：输入工具改为单行，修正宽度分配，并保留已放大的像素大小。
- 切屏时阻止新输入，但不能吞掉旧屏幕上按住的鼠标释放：释放仍发给同一有效且可控制的连接，
  旧连接或仅观看连接不能发送。
- 中文和组合快捷键作为有界批次整体入队，避免队列只接受 Ctrl 按下却丢失释放；
  给鼠标/按键释放保留容量。这里只保证整体入队，不声称网络断开后远端仍能整体收到。

  **不会点击 Windows 桌面、访问用户文件或控制真实远端**。
