# 中继选路：稳定优先，避免反复切换

1.0.24 在 Windows、Linux、Android 使用相同的偏好策略。它只影响之后建立的连接，
不迁移已建立的 TCP 会话，不切 Wi-Fi 名称，也不改变画质、帧率或编码参数。

## 规则

- 首次连接仍并发尝试经过证书指纹校验的 TLS 握手；已有首选时先尝试它，失败立即放行备用线路，原有 150 ms 兜底机制保留。
- 建连成功后可触发后台采样，同一中继最多每 30 秒一轮，整个选择器最多一轮在途。首帧启动前不等待采样；采样延后 1 秒，每轮网络等待预算 2 秒。
- 保留最近 8 次、最多 10 分钟的样本。比较中位耗时、P80 尾部波动和重复失败；单次尖峰或单次探测失败不单独触发调整。
- 候选至少有 3 个成功样本，最近 3 次均成功；综合分数至少改善 8 ms 且达到 25%，连续 3 轮满足条件，原首选已保持 180 秒，才修改首选。
- 正式连接失败不受三分钟限制；新 IP、网关、网卡或服务器身份改变后重新发现。十分钟没有新连接时偏好过期。
- 采样不发送中继访问令牌、设备密钥、注册或控制请求。取消后仍未结束的底层操作继续占用唯一采样名额，直到其资源确实释放，避免重连不断积累后台任务。
- Windows/Linux 在后台采样前复查网络；Android 还检查网络有效、非计费、无 VPN，不能为采样唤醒蜂窝网络。未满足条件时保留普通连接方式。

这里的失败是握手失败或超时，不是测量 UDP 丢包率；握手耗时也不等于完整远控延迟或吞吐量。
Windows 原有的临时路由保护规则仍保留，没有通过这次改动强制改写正在使用的路由。

## 核验

三端共同读取 `tests/data/relay-path-stability.tsv`，覆盖持续优势、逆向变化后的保持期、
抖动、单次尖峰、重复失败、立即故障回退、无效样本以及重复调用不能伪造连续证据。
另外检查了取消、晚到连接的关闭、采样任务数量上限，以及更新首选不会关闭已有连接。

本机双网卡对真实中继完成 217 秒、8 轮 TLS 采样，每轮均成功：

| 出口 | 平均握手耗时 | 中位数 | 最大值 |
|---|---:|---:|---:|
| Wi-Fi | 40.22 ms | 39.71 ms | 51.41 ms |
| 有线 | 33.20 ms | 32.65 ms | 41.21 ms |

此次持续差异没有达到切换门槛，隔离测试选择器保留首选 Wi-Fi，没有来回切换。
