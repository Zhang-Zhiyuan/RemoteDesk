2026-09-14。本轮已接入真实的 Windows 查看端接收、解码和显示流程，
**仍未达到发布条件，没有打包推送或覆盖安装**。普通客户端的启用开关默认关闭，

## 已完成

共享的版本表、分片和缓存代码迁到 `src/RemoteDesk.NativeDetail`，实验与应用使用同一份实现。
新增能力位 26、独立消息类型 7／8／9；不复用已有的诊断能力位 25，也不改变旧的视频头。
底图与完整版本表装在同一个经过 RDK1 认证加密的记录中，避免按相近到达时间拼接文字。
新记录有独立大小上限，仅在本地明确启用并确认对端能力后使用；目前不声明新方案的 UDP 支持。

原生身份经过 `RemoteFrame`、池化帧、解码输入映射传到正常查看窗口。
解码器统计信息仍可使用已有的近邻回退，但补清只接受精确的显式解码时戳和相符的图像尺寸。
丢失时戳、版本不符、底图积压或本地余量不足，直接显示底图。

接收线程只入一个有上限的队列，由单个后台任务解压；渲染只尝试获取缓存锁，拿不到就跳过。
队列最多 8 个分片，尚未显示的底图对应分片另保留最多 8 个；不等待这些分片。
它们仍受请求、版本、有效期和原有 2 个不完整块／64 个完成块的上限约束。
输入先失效旧请求，恢复需要在输入写完后发起新的本地请求，不能按“上一帧编号加一”猜测。

这次实际发现并修正：

- 已退役连接的 TCP 回调仍可能发布画面。现在检查连接归属和取消状态；对原来的普通画面也有效。
- 请求刚发出时，传输中的旧格式底图会错误取消新请求。首次新格式底图到达前允许继续显示旧底图，不叠字；
  新路径生效后再收到旧格式，才按后端回退失效补清。
- 断线时必须连“仅允许旧请求底图继续显示”的许可一起清掉，防止下一次连接复用。
- 解码输入映射丢失时不能把统计用的近邻帧身份带给补清。
- 关闭在本地立即生效，不等待能力协商、输入排空或网络写锁。新请求仍在途时，允许已确认的
  同会话同尺寸底图继续显示，但不叠加旧文字；一旦观察到新请求底图，立即结束这段许可。

## 实际验证

`artifacts/native-detail-session-20260914-r5`、`r6` 使用真正的
`RemoteViewerClient → RemoteViewerWindow → MF/D3D11`，不是绕过正常窗口的单独渲染器。
发送侧仍是隔离回环端点和预录测试素材，不冒充正式被控端。

r6 发出 138 帧，观察到 64 次原生 GPU 绘制。测试了中文输入送达合成对端、
输入后只继续底图、新请求恢复、调整窗口使旧视口失效，以及明确关闭。
未注入系统键鼠，没有修改本机剪贴板或连接已安装的远控节点。
补上即时关闭／在途底图保护后的 r7 再次通过：129 帧、62 次原生绘制，像素检查结果相同。

对两块 128×128 原图在 2:1 缩小后的 8,192 个显示像素，
实际窗口的逐像素结果与参考值最大相差 1 个 RGB 色阶，区域外全部不变。
其中 8,104 个像素不同于原 H.264 底图；该局部样本的 RGB RMSE 为 31.48 → 0.17。
这不是整屏清晰度评分，更不是公网时延或“GPU 零开销”的结论。
GPU 截图和逐像素比较不在实时呈现路径里，包含冷启动的遥测也不能用作开关前后延迟比较。

前几次失败记录也保留：r1 暴露在途旧格式底图取消请求的问题；r2／r3 的窗口被正常响应式布局
缩为 1748 像素宽，触发了大于 2 倍缩小的保护。r4 起在窗口 Load 完成后按真实操作调整大小，
没有放宽采样保护。r5／r6 加入了实际像素校验。

## 当时未完成的问题（后续已继续修复）

粗脏区饥饿、精确变化判定和新增重绘／DPI 核验的后续实现与结果见
[补清变化判定修复](NativeDetailRefinement-20260914.md)。下文保留本轮当时的原始结论；
新采集后端和公网调度的正式集成仍不能视为完成。

同源采集 r11 完成 240 帧、12 块准确读回、3 块编辑后文字、99 帧增强、30 帧繁忙跳过。
但 r12／r13 均出现 240 帧底图正常、补清完全没触发的情况。r13 的新日志显示：
236 帧的变化区域覆盖固定测试窗口内 `(0,26,2560,1414)`，所请求的 6 块版本不断更新，
共 1,410 次版本变化、1,434 次稳定期不足跳过，时间预算不足跳过为 0。
这是粗粒度变化区域导致无法满足 250 ms 稳定期；目前不能假定静态文字一定获得精细脏区。
必须研究精确且受预算约束的同源变化判定，不能直接忽略这些区域来强行保留旧文字。

之前采集 r5 的像素不匹配仍未重新捕获到，**不能声称已修复**。
现在失败时会保存实际块、原始／编辑后参考块、前 64 个异常像素、源帧身份、
绘制版本、DXGI 指针更新和变化区域信息，以便再次出现时定位，而不是反复跑到成功就算完成。
指针更新时间为 0 只表示没有指针更新，不代表指针被隐藏。

此外，正式 `RemoteHostServer` 的新采集后端选择、硬件故障回退和真实公网剩余带宽调度
还未接入；正常 UI 的视口请求管理、Linux／Android 对应接收呈现和手机实测也未完成。
不能拿本地回环的发送时间或人为预算证明公网不增加延迟。
