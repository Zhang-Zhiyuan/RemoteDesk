# Windows 控制端复制粘贴修正

1.0.16 的底层键盘转发路径直接发送了 Ctrl+V，却没有调用剪贴板同步。普通键盘事件中的同步入口也只对 Android 被控端启用。因此，本机复制的文字粘贴到 Windows / Linux 时可能没有反应，或粘贴远端旧内容。

现已将原生键盘转发和普通键盘事件接入同一粘贴流程：先同步、等远端确认，再执行快捷键。保留 Ctrl+Shift+V 和左右 Ctrl；不吞掉 AltGr 组合键，不提前释放仍按住的修饰键。重复按键、失焦和连接代次也有保护。

远端 Ctrl+C 后立即 Ctrl+V 会等待复制结果，避免用本机旧内容覆盖刚复制的远端文字。连续读取按顺序处理；非文本内容没有文字回复时，保留远端自身剪贴板。

## 核验

- 独立 Windows 窗口站、真实系统剪贴板、WinForms 窗口和加密测试连接：12 个场景通过，包含修复前可复现的失败。对端是受控测试程序，不是三台真机互控。
- 公网中继：9 项通过，涵盖文字发送确认、中文回传、文件校验、重名保留、空文件、失败回执和反向传输。使用临时测试节点，没有操作生产桌面或用户文件。
- Windows 回归：1910 通过，11 项环境门控测试跳过。

复现入口为 InteropProbe 的 `clipboard-shortcuts-isolated`。证据保存在本机 `artifacts/clipboard-shortcuts-20260912/`。本次修正发生在 Windows 控制端，需替换执行远控操作的 Windows 客户端；不是只更新中继服务器即可生效。

这不等于后台无条件同步所有剪贴板格式；Android 后台剪贴板限制仍存在。
