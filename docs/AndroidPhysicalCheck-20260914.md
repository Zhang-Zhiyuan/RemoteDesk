# vivo 真机检查（2026-09-14）

设备是 vivo X300 Ultra（Android 16 / API 36）。正式 APK 从 1.0.22 保留数据升级到
1.0.24，已核对安装包 SHA-256 与 `release/RemoteDesk-Android.apk` 相同。

结论：直连可正常控制，公网中继能连、能操作，但这次网络环境下的流畅度不合格。
没有把收到画面或早期 FPS 峰值当作流畅度通过。

## 实际连接

手机测试程序编译自当前产品 Java/资源，使用独立包名和数据区；Windows 和 Linux
目标是实际产品主机代码捕获的专用测试窗口。点击计数和中文/emoji 文本由目标操作系统
回读，不操作用户正在使用的其他窗口。公网组强制走原生 TLS 中继，无内网或 ADB 隧道回退。

| 手机控制目标 | 路径 | 观测呈现 FPS | 最后约 5 秒 FPS | 点击、中文输入 | ≥15 FPS 验收 |
| --- | --- | ---: | ---: | --- | --- |
| Windows | 内网直连 | 27.04 | 28.00 | 通过 | 通过 |
| Linux | 内网直连 | 27.33 | 29.92 | 通过 | 通过 |
| Windows | 公网中继 | 1.20 | 1.65 | 通过 | 未通过 |
| Linux | 公网中继 | 0.85 | 0.23 | 通过 | 未通过 |

四组最终都使用 1920×1080 H.264 Surface 硬解。FPS 由同一会话的实际呈现计数差计算；
直连观测约 14 秒，中继约 37 秒，并非长时间稳定性认证。

网络对照：

- 手机连接 HKUSTGZ，手机到网关平均 18.20 ms；到公网中继两轮平均 382.19 / 340.92 ms。
- 同期 Windows 到中继平均 14 ms，Linux 平均 319.54 ms；这些短测均未丢 ICMP 包。
- 手机产品网络代码三次 TLS 建连耗时 677～777 ms，均成功获取在线目录。
- 公网组主机日志出现持续 TCP 写入背压；本地 USB 测试流可呈现约 29 FPS。

这些结果指向公网路径的时延/吞吐瓶颈，不能归因于手机不支持硬解；也没有足够路由证据
断言流量绕经哪座城市。本轮未切换 Wi-Fi、启用蜂窝流量、改服务器或降低图像设置。
本轮只测试当前 Wi-Fi，没有接入第二条免流量计费网络，因此不构成真机多网卡切换/防抖认证。

注意：正式 App 当前未显示有效的中继登录。上述公网测试临时复用了电脑已验证的中继
授权，仅存入独立测试程序；没有把它写进正式 App，因此不能说手机正式 App 已登录中继。

## 交互与回归

通过独立测试程序和本地加密测试流（此部分经 ADB reverse，不作为公网性能证据）：

- 41 项交互检查：点击、拖动、中文输入、横竖屏、全屏、画质/屏幕切换、受控断线重连。
  包括重连不重放旧输入、等待新画面时隐藏旧 Surface 并阻止输入。
- 37 项双指滚动检查：手指抖动、批量事件中的反向滚动、换指、缩放误判；使用生成的
  MotionEvent，不代表真人主观手感或真实网页滚动延迟。
- 10 个 Surface/键盘/缩放场景：保持源分辨率缓冲、1:1 像素、输入时不再次缩小文字。
- 240 / 320 dp 两种窄布局，各 11 次坐标点击，包括缩放和新版放大按钮。
- 单线路超时取消约 151 ms，等待中的 socket 已关闭。

本轮修的是测试工具：补齐新版工具栏回调、让 UI 检查能在窄屏左右滑动找按钮；给公网
实测增加经校验的 stdin 配置入口，避免再次索取管理员密码。POSIX 文件权限用例标明
Linux 条件，并在 Linux 真实执行，没有用 Windows 模拟权限结果。

Python 回归共 577 项：Linux 573 通过、4 跳过；Windows 528 通过、49 跳过。
Android 测试 APK 重新构建成功。正式应用代码/画质算法本轮未修改。
