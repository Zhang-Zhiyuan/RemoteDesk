# 右键复制粘贴修复（2026-09-19）

原来的自动同步由 Ctrl+C/X/V 等快捷键触发。鼠标菜单不经过这些入口，因此右键操作时两边的文本剪贴板可能仍是旧内容。

## 修改

- Windows 查看窗口增加文本变化检测，前台每 500 ms 检查一次。远端内容没变只返回修订信息，不反复传正文；初次连接只建立基线，不拿远端旧内容覆盖本机。
- 本机新复制的文字会发送并等待确认；右键菜单前补齐尚未同步的文本。等待期间的按下、松开和后续菜单点击按原顺序处理，焦点释放、断连和重连会使过期输入失效。
- 远端新复制的文字会取回。本机在等待期间又复制了内容，迟到回复不会覆盖它。自动写回不会循环回传；重新复制相同文字仍按新复制处理。
- 文件、图片和空剪贴板不当作文本自动上传，也不清空本机；文件传输仍走原确认流程。超大文本或写入失败会提示，保留远端原生右键菜单，不禁用“复制”等无关操作。
- Windows、Linux、Android 被控端增加协商后的带请求 ID 快照消息。旧端不接收不认识的消息，原快捷键和手动按钮保持兼容。协议仍使用现有加密连接，未增加端口或修改中继服务。
- 快照的 8 秒截止时间包含排队发送。超时后只读发送最多保留一个，不中断半个 TCP 数据包、不堆积新请求，迟到结果因请求 ID 失效而被丢弃。

窗口失焦约一秒后不再发新轮询；已经发出的有界请求允许完成，方便从远端复制后切回本机粘贴。其结果仍受本机剪贴板序号、会话和当前远控窗口归属检查。

## 生效范围

这是 **Windows 查看端**的右键自动文本同步修复。主控及被控端都需要更新才能使用新变化反馈；连接旧被控端时仍保留旧快捷键/按钮功能。本轮没有新增 Linux/Android 查看端的自动菜单同步；Android 被控端仍受系统后台剪贴板读取限制，不把权限拒绝当作空内容。

本轮没有进行三台物理设备或公网中继端到端复测，也没有替换正在运行的安装、发布包或 GitHub Release。构建与源码修复已完成，不能据此认为线上旧版本已生效。
