## 本轮修正

本轮改动均为测试/验收工具，**没有修改或重新发布产品源码、替换正式安装包**。

1. Windows JPEG 验收改为统计实际 Paint 事件中的不同位图。原定时采样只记录到
   3 次变化，实际却绘制了 347 张不同画面，导致误报“未持续呈现”。修正后直连
   复测收到 486 帧、绘制 440 张，中转收到 49 帧、绘制 42 张。不同运行时长和指标
   不可直接比较 FPS。[WM_TIMER 是低优先级消息](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-timer)。
2. 手机既有连接参数提前从 stdin 消费；无输入载荷的子进程关闭 stdin，避免 SSH
   子进程吞掉稍后要读取的手机参数。正式版口令只在内存和输入管道内复用，不读取
   正式版私有目录，不重置密码，不写入报告。
3. 手机测试目标增加前台状态与启动结果记录。第一次中转手机阶段没有保持测试
   Activity 在前台，读到了上轮结果；立即停止临时服务，保留失败记录。修正后
   拒绝后台/陈旧结果，隔离中转测试主机失焦自动停止；两个中转方向以及正式版
   手机直连两个方向重新通过。停止逻辑只作用于隔离 APK，不影响正式 App。
4. 新增 7 项无设备回归，覆盖 stdin 隔离、错误信息不回显参数、拒绝正式 App
   作为合成输入目标、拒绝旧/后台手机状态等。

Windows 目标也曾两次失去前台，安全保护中止测试，没有放宽断言。Android→Windows
在独占窗口下另行复测通过。所有失败证据保留，不将其改写成成功。

## 额外检查与回归

对已安装的手机正式版，经真实 LAN TCP 验证了以下协议行为（不注入 OS 输入）：

- 错误密码明确返回认证拒绝，原会话仍能继续收帧。
- 新的认证查看端接管后，旧查看端被断开，新端收到 H.264 帧。
- 断开后再次认证连接，继续收到 JPEG 帧。
- 恢复手机正式版被控时，再次验证自动返回桌面，未用 ADB Home 代替该断言。

自动化回归：Windows **1572 通过、11 环境跳过**；Android Debug **392 通过**、lint
无问题；Python **278 通过、5 环境跳过**。跳过项不算通过；本轮未重跑 Android
Release 单元测试，不能把此前 Release 结果并入本轮。

Jetson 被控仍是 JPEG 回退；本轮中转帧率较低且有波动，**不能据此宣称中转已流畅或
固定高 FPS**。没有通过降低画质来放宽断言。Jetson 查看端硬解后仍回读 CPU 并经
Tk 显示，不是零拷贝。Windows 测试源是 4K 主屏按 50% 缩放；手机也不是原生全分辨率。

三台设备可同处一个局域网，只是中转数据强制经公网，不代表不同运营商/NAT 或
漫游切换实测。未覆盖长时间无人值守、原生 Wayland/登录界面、全部文件操作、
多屏/快捷键，以及真实断网后完整 App 界面的自动重连，不能承诺“没有 bug”。
