# 复制粘贴与文件传输检查

## 修复

Windows 远控窗口的全局键盘钩子只检查了画面控件焦点，没有检查前台窗口。
切回本机后，如果远控窗口的异步操作恢复画面焦点，Ctrl+C 会被误发给远端。
现在只有已连接、位于前台且画面获得焦点的远控窗口才拦截按键。
该修复位于 Windows 控制端，对连接 Windows、Linux 或 Android 均有效，不修改协议。

补充了粘贴阶段、远端确认和超时诊断。只记录状态、长度和连接编号，不记录复制内容。

## 验证

- 两个真实 Windows 窗口、独立 UI 线程、加密本机测试连接。模拟后台异步恢复焦点后，旧版拦截了 Ctrl+C 的四个按键事件，测试端收到一次误复制；新版均为零，前台复制仍通过。测试直接调用产品键盘回调，不向用户桌面注入按键。
- 独立窗口站验证文本、中文文件路径、空回复保护、旧回复保护，以及 Ctrl+V、右 Ctrl、Ctrl+Shift+V、Shift+Insert、连续复制和失焦取消。
- 经已有公网中继验证文字往返、1 MiB 文件上传与回传、中文/表情文件名、同名保留、空文件和接收失败反馈。使用临时节点与产品文件接收器，不连接用户正在使用的设备。
- 文件粘贴确认弹窗另在交互桌面运行：取消不发送，确认后文件逐字节一致。输入是生成的测试路径，不读取用户剪贴板；文件剪贴板读取在独立窗口站单独验证。
- Windows 全量回归：2,207 通过、11 项硬件/真机门控测试跳过。Linux/WSL 剪贴板 19 项和文件相关 56 项通过，包括独立 Xvfb 的系统剪贴板。

本轮未检测到 USB 手机，Linux 真机的 SSH 地址也未连通，不把它们计作真机通过。
保留现有用户配置和文件。本地证据在 `artifacts/clipboard-files-20260918/`。

焦点与前台窗口的区别见 [Windows GetFocus 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getfocus)。
