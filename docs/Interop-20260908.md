# 三端互联互通实测：20260908 批次

> 公开副本：历史记录中的设备及服务器地址已脱敏为示例地址，不是可连接的真实目标。

## 结论与测试范围

Windows、Linux、Android 六个控制方向均通过本轮短时实机检查：持续呈现画面、目标系统实际点击、中英文输入；另通过 Windows 重连 Android 检查。这不是全功能、长时间稳定性或“没有 bug”的认证。

设备为 Windows x64（198.51.100.79）、Jetson Orin ARM64 Linux（198.51.100.74）、realme GT8 Pro / Android 16（203.0.113.214）。所有会话通过真实局域网地址连接，没有使用 SSH/ADB 端口隧道代替网络测试。

Windows 使用当前源码的实际服务端、客户端和 WinForms/D3D 显示组件，运行于独立诊断程序，不占用原 App 的服务端口。Linux 使用暂存的当前产品源码，捕获及显示目标为独立 Xvfb/Tk 测试桌面，不是用户的原有桌面。手机控制端使用编译实际产品 Viewer 的隔离测试 APK；手机被控端使用原已安装的正式应用包，通过正常系统界面授权屏幕共享。

## 实测矩阵

方向为“控制端 → 被控端”。每行均验证实际目标按钮计数及精确 Unicode 文本，不只检查输入消息是否发出。

| 方向 | 视频与显示证据 | 点击 / 文字 |
| --- | --- | --- |
| Windows → Linux | 1920×1080 JPEG；收到 489 帧，实际 PictureBox 图像更新 95 次 | 通过 |
| Android → Linux | 1920×1080 JPEG；末次呈现状态 30 FPS，TCP | 通过，含原生输入法中文组合与 emoji |
| Linux → Windows | 1920×1080 H.264；314 次 Tk 显示更新，242 次像素变化；持续 Jetson V4L2 硬解 | 通过 |
| Android → Windows | 1920×1080 H.264 Surface 硬解；末次状态 26 FPS，UDP 视频 / 鼠标输入 | 通过，含原生输入法中文组合与 emoji |
| Windows → Android | 734×1600 H.264；收到 530 帧，MF/D3D11 实际呈现 518 帧 | 通过 |
| Linux → Android | 734×1600 H.264；619 次 Tk 显示更新，616 次像素变化；持续 Jetson V4L2 硬解 | 通过 |

Windows → Android 断开后重连也通过：收到 545 帧，MF/D3D11 呈现 531 帧，目标再次收到点击及完整中英文文本。

这些帧数、像素变化数和末次 FPS 是不同指标，不能直接横向比较性能。桌面控制端通过实际产品客户端输入接口注入；Android 控制端额外经过实际 Viewer 触摸和原生 InputConnection 组合输入流程。尚未穷举桌面 GUI 的全部键盘钩子及快捷键映射。

## 本轮修复

1. **Linux 鼠标可用但文字无反应。** 原生 XTest 已启用时，文字辅助程序被错误地视为不可用。现在独立检测和使用 xdotool，仅补充 Unicode 文字路径，不改变原生鼠标、物理按键的权限与后端限制。
2. **Linux 中文漏字。** 真机在 xdotool 零延迟临时键位映射时丢失第二个中文字；改为 12 ms 间隔后，中文和 emoji 精确匹配。辅助程序超时及失败信息不再回显可能含输入内容的命令参数。
3. **Linux 缺失文字输入依赖未申请安装。** xdotool 加入固定依赖清单，即使 XTest 可用也会检测，继续走原有用户确认和系统提权安装流程。
4. **Jetson 硬解误回退。** Jetson 的正常帧关联滞后允许到 3，其余后端仍为 2；先消费已完成的待取帧，再预留新输入槽，避免把可消费输出误判为拥塞。关联容量上限仍为 4，并补充 FIFO 和边界测试。
5. **手机 H.264 流触发 Jetson 中间 MJPEG 编码器退出。** 实测捕获到重复时间戳错误 `Invalid pts (3) <= last (3)`。仅对 Jetson 本地 MJPEG 管道设置单调帧序号时间戳 `settb=expr=1/60,setpts=N` 与 `-enc_time_base 1:60`，不修改网络 H.264 流或其帧率。修复后分别重测手机和 Windows 视频源，均持续使用硬解。参数含义参见 [FFmpeg setpts](https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts)、[settb](https://ffmpeg.org/ffmpeg-filters.html#settb_002c-asettb) 及 [编码器时间基准选项](https://ffmpeg.org/ffmpeg.html)。
6. **Linux 本地画面转换开销。** Tk 显示所用 PNG 压缩级别由默认 6 改为 1；仍为无损像素，不改变网络压缩质量或码率。

Jetson 上同一张 1920×1080 测试图按 1280×820 显示区域适配，30 次样本的本地转换耗时中位数从 **147.19 ms 降至 94.29 ms，约减少 36%**。两种设置的解码像素 SHA-256 完全一致。本地 PNG 大小从 544,409 增至 567,045 字节；此数据不经过远程网络。这不是端到端延迟降低 36% 的结论。

## 尚存边界与交付状态

- **Jetson 被控端仍为 JPEG 回退。** 可发现的 H.264 编码器未通过实际首帧编码探测；本轮没有补齐 Jetson 硬件编码实现，不能承诺这两个方向与 H.264 一样流畅。
- **Jetson 控制端还不是零拷贝。** 当前为 GPU 解码后回读 CPU，经 MJPEG、PNG/Tk 显示。最终单次采样的接收至 PNG 就绪耗时约为手机源 188 ms、Windows 源 356 ms；不是纯解码耗时，也不是网络 RTT，仍有优化空间。
- Linux 原生用户 Xorg/Wayland、登录屏幕、公网中继、长时间无人值守、文件传输、锁屏/后台、所有多屏/DPI/快捷键组合不在本轮验收范围。
- 修复已落实到源码并在暂存版本实测；**没有替换正式 Windows/Android 发布包或部署新的常驻 Linux 版本，也没有提交或推送 GitHub**。原有工作区改动保留。
